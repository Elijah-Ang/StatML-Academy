      - paragraph: To know whether a model can handle new cases, some examples must remain outside the learning process. Each split has one job and should not quietly take on another.

      - paragraph: The representation determines what relationships are easy to learn. Images need nearby pixels to stay nearby, text needs token order, and audio needs precise changes through time. Preprocessing is therefore part of the model’s language, not mere housekeeping.
      - generic: How it works
      - list:

        - generic: "2"

        - generic: "3"

      - paragraph: The same resize, tokeniser, vocabulary, sample rate, and normalisation must be used during training and real use. Changing them changes what the numbers mean.

      - heading "Depth builds features" [level=2]: Depth builds features
      - paragraph: A deep network turns the same example into a sequence of increasingly useful descriptions. Each layer receives the previous layer’s features and composes them into larger ideas.
      - generic: Why it matters
      - paragraph: Raw pixels are a poor language for “dog.” Edges are more useful; groups of edges can describe fur or curves; those patterns can form ears, eyes, and snouts. Hierarchy lets the model reuse simple discoveries to build complex ones.
      - generic: How it works
      - list:
        - generic: "1"
        - paragraph: Early layers respond to local changes such as edges, colour transitions, or short sound patterns.
        - generic: "2"
        - paragraph: Middle layers combine repeated local clues into textures, shapes, or meaningful phrase fragments.
        - generic: "3"
        - paragraph: Later layers gather evidence across a wider area and make features useful for the final task.
      - paragraph:
        - strong: "Picture it:"
        - text: It is like looking through a stack of tracing sheets. Each sheet redraws the scene using the patterns that matter at its level.
      - paragraph: The feature names are a helpful simplification, not rules written by a programmer. Training discovers the filters that reduce the loss.
    - article:
      - generic: "07"
      - paragraph: The correction cycle
      - heading "How learning happens" [level=2]: How learning happens
      - paragraph: Learning is a repeated correction loop. The network guesses, measures how wrong it was, works out which parameters influenced the mistake, and makes a small adjustment.
      - generic: Why it matters
      - paragraph: A loss number alone says only “this was wrong.” Backpropagation turns that complaint into useful directions for millions of parameters, allowing each one to change in proportion to its contribution.
      - generic: How it works
      - list:
        - generic: "1"
        - paragraph: Forward propagation moves a batch through the layers and produces predictions.
        - generic: "2"
        - paragraph: A loss function compares predictions with the correct answers; backpropagation calculates gradients from output to input.
        - generic: "3"
        - paragraph: An optimiser uses those gradients to update the weights. The learning rate controls how large each step is.
      - paragraph:
        - strong: "Picture it:"
        - text: Imagine descending a foggy hill. The gradient tells you which way slopes downward; the learning rate decides whether you take careful steps or dangerous leaps.
      - paragraph: One update teaches very little. Useful behaviour emerges from many batches of examples providing many small, partly noisy corrections.

      - heading "Choose an architecture" [level=2]: Choose an architecture
      - paragraph: An architecture is a set of useful assumptions about how information is organised. The right design makes important patterns easier and cheaper to learn.
      - generic: Why it matters
      - paragraph: Images contain many local patterns, not one universal feature. Sequences need memory or direct links across time. Architecture decides how information is shared, how far context can travel, and what the model can compute efficiently.
      - generic: How it works
      - list:
        - generic: "1"
        - paragraph: A CNN layer learns many filters. Every filter scans every image, producing its own feature map. Training changes the filter values; testing reuses the learned filters without inventing new ones.
        - generic: "2"
        - paragraph: An RNN reads one item at a time and updates a hidden state—a fixed-length vector that compresses what it has seen. That state can produce scores for the next word or another sequence output.
        - generic: "3"
        - paragraph: A Transformer creates a query, key, and value for every token. Query–key matches become attention weights, which gather useful values into context. Training rewards links that help reduce prediction error.
      - paragraph:
        - strong: "Picture it:"
        - text: "Choose a tool shaped like the material: a movable stencil for space, a notebook passed through time, or a web of spotlights for attention."
      - paragraph: Choose with evidence, not fashion. CNNs remain natural for spatial data. RNNs can suit compact streaming systems. Transformers usually handle long context and parallel training better, but standard attention can require much more memory as a sequence grows.

      - paragraph: A model can reach 95% accuracy by always predicting the common class in an imbalanced dataset. In medicine, fraud, or safety, one missed positive can matter far more than one false alarm.

      - heading "Ship the whole pipeline" [level=2]: Ship the whole pipeline
      - paragraph: A deployed model is not only a weights file. It is a complete, repeatable route from raw input to a decision that behaves the same way outside the training notebook.
      - generic: Why it matters
      - paragraph: A brilliant model can produce nonsense if the live system resizes differently, swaps class order, forgets normalisation, or leaves dropout active. Most production failures happen at the seams around the network.

        - generic: "3"
        - paragraph: Test the complete pipeline in its target environment for latency, memory, privacy, energy use, throughput, and failure handling.
