01A basket becomes a row

What are we counting: products or baskets?

We count shopping baskets. Each basket is one transaction. An item is one product, such as Apple. An itemset is a group of products, such as Apple + Coke. We count a basket if it has every product in that group. Three apples in one basket still count as one basket.

The four baskets we will keep using

TID (transaction ID)Items in the basket
100Apple, Coke, DVD
200Bread, Coke, Egg
300Apple, Bread, Coke, Egg
400Bread, Egg

A = Apple, B = Bread, C = Coke, D = DVD, E = Egg. The pictures use these letters when the full names would take too much room.

Each basket becomes a row of yes/no answers. This is called a Boolean row: 1 = the item is there, 0 = it is not there. TID is just the basket’s ID number. It is not a product.

Why this works · a little deeper

A, B, C, D and E stand for the five products listed above. A 3-itemset is a group of three different products. It does not mean three units of one product.

Decide what one row means before looking for patterns. Is it one shopping trip, everything a customer bought in a month, or one product record? These choices answer different questions. Here one row is one basket. We only ask whether an item is there, so buying more units does not add more counts.

The Python practical uses MP3 where the lecture uses DVD. The same four rows have the same yes/no pattern, but MP3 and DVD are different products.

Quick check · One basket has three apples. Does it count as three Apple baskets?

No. There is only one basket. It contains Apple, so it adds one to the Apple count.

Now we know what a basket and an item mean. Next, use them to read an arrow.

Next: A rule has two sides ↓
02A rule has two sides

What does Apple → Coke mean?

Apple → Coke asks: “Of the baskets with Apple, how many also have Coke?” The left side is called the antecedent, or X. The right side is the consequent, or Y. Each side needs at least one item, and an item cannot be on both sides. The joint count is the number of baskets with all the items from both sides.

Read the arrow as a question

X = {Apple}
Y = {Coke}
X ∪ Y = {Apple, Coke}

The symbol ∪ joins the item names: X ∪ Y means {Apple, Coke}. Baskets 100 and 300 have both. The arrow tells us which group to look at first. It does not tell us which product was bought first.

Source: Lecture pp.13–14. The example on this page stays the same when you change the interactive picture.

↳
Try it

Choose Bread + Coke → Egg. First find the baskets with both Bread and Coke. Then check which of those baskets also have Egg.

Why this works · a little deeper

Bread + Coke means both items must be there. A basket with only Bread does not count for that left side. The same rule applies when the right side has several items.

X ∪ Y joins a list of item names. To count a basket, it must contain all of those items. Do not read the symbol as “Apple or Coke”. In probability, requiring both events is called an intersection.

An association rule describes items appearing together. It does not show that one item caused the other. It also does not, on its own, show that the pair appears together more than we would expect. We will check that later using lift.

Quick check · Is Apple + Coke → Coke allowed here?

No. Coke is on both sides. If the basket already has Coke on the left, finding Coke on the right tells us nothing new.

We can read the rule. Next, count how often both sides appear together.

Next: Support counts everybody ↓
03Support counts everybody

What fraction of all baskets has both items?

Support tells us how common a group of items is across all baskets. For Apple → Coke, count baskets with both Apple and Coke. Then divide by the total number of baskets. The bottom number of this fraction is called the denominator. Include every basket in that bottom number, even one with neither item.

Use all four baskets on the bottom

count({Apple, Coke}) = 2
support(Apple → Coke) = 2/4 = 50%

Baskets 100 and 300 have both items, so the top number is 2. There are four baskets in total, so the bottom number is 4. Baskets 200 and 400 still count in that total, even though they have no Apple.

Source: Lecture pp.13–17; recurring four-basket example. The example on this page stays the same when you change the interactive picture.

↳
Try it

Choose Bread → Egg. Count the green baskets. Divide that count by four. Is its support higher or lower than Apple → Coke?

Why this works · a little deeper

A support count is just a number of baskets, such as 2. Relative support turns it into a fraction: count ÷ total baskets. We often call the total N. Two matches out of four is 50%. Two matches out of one hundred is only 2%.

Support does not depend on which way the arrow points. Apple → Coke and Coke → Apple count the same baskets with both items.

If we add baskets with neither item, the top number stays the same but the bottom number grows. Support goes down. You can try this in section 15.

Coffee → Milk3 / 6 = 50%

Quick check · Is the support of Apple → Coke 2/2?

No. Support uses all four baskets, so it is 2/4 = 50%. The fraction 2/2 only looks at the Apple baskets. That is the next idea: confidence.

Support looked at everybody. Next, look only at baskets with Apple.

Next: Confidence zooms into X ↓
04Confidence zooms into X

Of the Apple baskets, how many also have Coke?

Confidence looks only at baskets with the items on the left side, X. Of those baskets, how many also have the right side, Y? For Apple → Coke, keep the Apple baskets and check how many have Coke. This time, the bottom number is the number of Apple baskets.

Keep only the two Apple baskets

confidence(Apple → Coke)
= count({Apple, Coke}) / count({Apple})
= 2/2 = 100%

For support, we divided by all four baskets. For confidence, we keep just baskets 100 and 300 because they have Apple. Both have Coke too. That gives 2 out of 2, or 100%.

Source: Lecture pp.15–17. The example on this page stays the same when you change the interactive picture.

Try it

Choose Bread → Coke. Three baskets have Bread. Which of those has no Coke? It still counts on the bottom of the confidence fraction.

Why this works · a little deeper

You may see confidence written as P(Y | X). The vertical line means “given”. Read it as “how often Y appears, given that X is there”. It describes the baskets we have seen. It does not promise what the next customer will buy.

If no basket has X, we would have to divide by zero. We cannot calculate confidence in that case. The picture shows “Undefined”.

High confidence can happen because Y is already very common. Before calling the pattern unusual, we need to know how often Y appears in all baskets.

In the separate six-person lecture example, four people buy Coffee and three of them also buy Milk. Confidence is 3/4 = 75%. Support still uses all six people: 3/6 = 50%. The top number is three in both calculations.

Quick check · Three baskets have X. Two of those also have Y. What is confidence?

2/3, or about 66.7%. The third basket has X but no Y. It stays in the group we are checking, so it stays on the bottom.

The left side picked the group. Next, reverse the arrow and see what changes.

Next: Reversing the arrow ↓
05Reversing the arrow

Does Coke → Apple give the same answer?

The number of baskets with both items stays the same when we reverse the arrow. Support stays the same too. Confidence can change. Apple → Coke divides by Apple baskets. Coke → Apple divides by Coke baskets.

Same pair, different starting group

RuleSupportConfidence
Apple → Coke2/4 = 50%2/2 = 100%
Coke → Apple2/4 = 50%2/3 = 66.7%

Baskets 100 and 300 have both items in either direction. That is all 2 Apple baskets, but only 2 of the 3 Coke baskets. So the confidence changes from 100% to 66.7%.

Why this works · a little deeper

For any valid rule, reversing the arrow keeps support the same. Confidence uses count(X) in one direction and count(Y) in the other. Those counts may be different.

The arrow is the direction of our question. It is not the order in which someone bought the products. Finding patterns in purchase order is a separate task called sequential pattern mining.

The seminar’s computer example works the same way. CPU → GPU has 20% confidence. GPU → CPU has 80%. Both use the same 1,200 records with both parts, but they divide by different group sizes.

Quick check · Both directions have the same confidence, and at least one basket has both items. What must be equal?

The two starting groups must be the same size. We have the same positive top number in both fractions. To get the same answer, the bottom numbers must match too.

Confidence tells us about one group. Next, compare it with how common the right-side item is overall.

Next: Lift checks the baseline ↓
06Lift checks the baseline

Is the right-side item more common in this group than overall?

First ask how often Y appears in all records. That rate is our baseline, or starting point for comparison. Lift = confidence ÷ baseline. A lift above 1 means Y is more common in the X group than overall. Below 1 means it is less common. At 1, the rates are equal.

A separate example: basketball and cereal

N = 5,000; Basketball = 3,000
Cereal = 3,750; Both = 2,000
confidence = 2,000/3,000 = 66.7%
baseline = 3,750/5,000 = 75%
lift = (2/3)/(3/4) = 8/9 ≈ 0.89

If cereal were equally common among basketball players and all people, we would expect 3,000 × 3,750 / 5,000 = 2,250 people to do both. The data has only 2,000. Cereal is less common among basketball players than it is among all 5,000 people.

Why this works · a little deeper

Lift gives the same answer in either direction. Another way to calculate it is support(X ∪ Y) ÷ [support(X) × support(Y)]. For Apple and Coke, that is (2/4) ÷ [(2/4) × (3/4)] = 4/3 ≈ 1.33. Both items need positive support for this calculation.

Above 1, the pair appears together more often than we would expect if the items were unrelated. Below 1, it appears together less often. This is called positive or negative dependence. At exactly 1, the two yes/no events are independent in this dataset, as long as both items appear at least once.

A lift near 1 in a small sample does not prove the items are unrelated everywhere. Lift also does not tell us how much a promotion would change sales.

The number with both cannot be bigger than either group. It also cannot be so small that the groups no longer fit inside the total N. The full bounds are max(0, count(X) + count(Y) − N) ≤ count(X ∪ Y) ≤ min(count(X), count(Y)). The slider stays within these limits.

For Burger → Ketchup, the practical gives 5% support, 33.3% confidence, and lift 3.33. Ketchup appears in 10% of all records. That 10% is the baseline for Ketchup; it is not the rule’s support.

Quick check · Cereal appears among 66.7% of basketball players and 75% of all people. Is it more common among basketball players?

No. 66.7% is below 75%, so lift is about 0.89. This describes the data. It does not show that basketball caused the difference.

We can compare a rule with the baseline. Next, choose the minimum scores it must pass.

Next: A strong rule meets two cutoffs ↓
07A strong rule meets two cutoffs

Which rules pass our two minimum scores?

We choose two cutoffs: minimum support and minimum confidence. A group of items is frequent if it meets the support cutoff. A rule is called strong if it meets both cutoffs. First find the frequent groups. Then check the rules we can make from them. A score exactly on a cutoff passes.

Why this works · a little deeper

The five passing rules at the original cutoffs are Apple → Coke, Bread → Egg, Egg → Bread, Bread + Coke → Egg, and Coke + Egg → Bread.

If the baskets stay the same, raising minimum support cannot add a frequent itemset. Lowering minimum confidence can let more rules pass, but their support still has to pass too.

“Strong” only means the rule passes the cutoffs. It does not automatically mean useful, surprising, or caused by one item. It does not prove the pattern goes beyond chance. A low support cutoff can reveal rare patterns, but it often gives us many more groups and rules to check.

Quick check · A rule has 49% support and 100% confidence. Does it pass a 50% support cutoff?

No. It must pass both cutoffs. Perfect confidence cannot make up for support below 50%.

We need frequent itemsets before making strong rules. Next, learn a shortcut for finding them.

Next: Apriori prunes supersets ↓
08Apriori prunes supersets

Why can adding an item never give us more matching baskets?

A basket with Bread + Coke + Egg must also have Bread + Coke. Adding Egg makes the requirement stricter. It cannot add new matching baskets. The smaller group is a subset. The larger group is a superset. If the smaller group fails minimum support, every larger group containing it must fail too.

More required items means no more matches

count({Bread, Coke, Egg}) = 2
count({Bread, Coke}) = 2
count({Bread}) = 3

DVD appears in only one basket. We require at least two. Any group containing DVD can appear in at most that one basket, so it must fail. We can skip checking all those larger groups.

Source: Lecture pp.21–24; textbook §6.2.1. The example on this page stays the same when you change the interactive picture.

↳
Try it

Look at Bread + Coke + Egg, then Apple + Bread + Coke. Check each pair inside the three-item group. Can you find a pair that already fails and rules out the whole group?

Why this works · a little deeper

This shortcut is the Apriori property. If a group is frequent, every smaller nonempty group inside it is also frequent at the same cutoff. Turn that around: if a group fails, adding more items cannot rescue it. Skipping those larger groups is called pruning.

The reverse is not guaranteed. Apple and Bread may each be common, but they may rarely appear together. Even when every pair is frequent, the full three-item group can fail. The pairs might appear in different baskets.

This shortcut works for support because adding items cannot increase the count. Confidence changes its starting group, so it does not follow the same general rule. We cannot use a confidence cutoff as a replacement for this support check.

Quick check · Apple and Bread each pass the support cutoff. Must Apple + Bread pass too?

No. Each item appears in at least two of our four baskets. Together, they appear only in basket 300. One match is below the required two.

Now use that shortcut in Apriori: join groups, remove impossible ones, then count.

Next: Apriori joins, prunes, counts ↓
09Apriori joins, prunes, counts

How does Apriori find bigger groups one step at a time?

Apriori checks one-item groups, then two-item groups, then three-item groups. A possible group is a candidate. Cₖ means candidates with k items; Lₖ means the ones that passed support. To make the next level, join passing groups. Skip a new group if one of its smaller groups failed. Then count the remaining candidates in the baskets.

The four lecture baskets, with at least two matches required

LevelFrequent sets (support count)
L₁A:2, B:3, C:3, E:3
L₂AC:2, BC:2, BE:3, CE:2
L₃BCE:2
L₄Empty, so stop
Join BC + BE → BCE
Check BC, BE, CE in L₂
Count matching baskets 200 and 300 → 2
2 meets the cutoff → keep BCE in L₃

A = Apple, B = Bread, C = Coke, D = DVD, E = Egg. AB and AE each appear once. They fail when we count them. BCE appears in baskets 200 and 300, so it passes.

Source: Lecture pp.23–28; textbook §§6.2.1–6.2.3. The example on this page stays the same when you change the interactive picture.

Try it

Start at level 3. BC and BE join to make BCE. Check that CE also passed. Go back to level 2 and look at AB: it fails after counting. For a group skipped before counting, set support to 25%, return to level 3, and choose ADE. DE is missing from the passing pairs.

Why this works · a little deeper

Keep the item letters in the same order. To build a k-item group, join two passing (k − 1)-item groups whose first k − 2 items match. For example, BC and BE share B and make BCE. Check every group made by removing one item: BC, BE and CE. Only then count BCE itself.

The lecture writes the baskets using letters such as A,C,D and B,C,E. They are the same yes/no patterns as our named baskets. D stands for DVD.

Apriori may read the baskets many times and make many candidates. There are ways to reduce this work. Hash buckets group candidates and rule out groups with too few possible matches. Transaction reduction skips baskets that cannot hold a longer passing group. Partitioning finds possible groups in smaller chunks, then checks them against all the data. Sampling uses only part of the data; it can miss patterns unless we do suitable follow-up checks. Dynamic counting starts checking new candidates partway through a scan.

At 50% support, the ordered join makes just one triple: BCE. Missing passing pairs already block the Apple triples. At 25%, AD and AE can join to make ADE. But DE has count zero, so we skip ADE before scanning the baskets for it.

Quick check · Every smaller group passed. Can we keep the new group without counting it?

No. It is worth checking, but it has not passed yet. Count the full group and compare that count with minimum support.

We have found the frequent groups. Next, turn each group into arrows.

Next: An itemset becomes several rules ↓
10An itemset becomes several rules

How can Bread + Coke + Egg make six different rules?

Take a group of items and split it across an arrow. Each item goes left or right. With three items, that gives 2 × 2 × 2 = 8 choices. Remove the two choices with an empty side, leaving six rules. For k items, we write this as 2ᵏ − 2. The items stay the same, so support stays the same. Confidence can change because the left side changes.

Why this works · a little deeper

The two excluded choices put all the items on one side and none on the other. Both sides must have something. If the right side has several items, a basket must have all of them to count as a match.

The whole itemset must pass support for any of its rules to be strong. This picture still lets you explore its splits if your edits make it fail. It labels those rules as failing support.

Finding frequent groups and making rules are separate steps. Apriori and FP-growth use different ways to find the groups. If they find the same groups and counts, we can use the same method to turn either result into rules.

Quick check · For Bread + Egg → Coke, do we divide by the number of Bread baskets?

No. The left side requires both Bread and Egg. Three source baskets have both, so confidence is 2/3.

Apriori checks candidates in stages. Next, see how a tree can store shared parts of baskets.

Next: FP-trees share prefixes ↓
11FP-trees share prefixes

How does a tree save repeated parts of baskets?

An FP-tree stores baskets as paths that can share their starting steps. First remove items below the support cutoff. Put the remaining items in one fixed order, with common items first. A shared start is called a prefix. When the next basket follows an existing path, reuse it and add to its counts. Make a new branch where its path differs.

A separate five-basket example from the lecture

TIDFrequent items in global order
100f, c, a, m, p
200f, c, a, b, m
300f, b
400c, b, p
500f, c, a, m, p
Minimum support count = 3
Header: f:4, c:4, a:3, b:3, m:3, p:3

The letters f, c, a, b, m and p are item names for this separate example. They do not stand for Apple, Bread, Coke, DVD or Egg.

The header counts each item across all five baskets. In the tree, ∅ is the empty starting point, called the root. It is not an item. A label such as c:3 means three baskets followed that path to c. Another branch has c:1. Together, they give the header count c:4.

Both f and c appear four times. The lecture puts f first when their counts tie. Use that same order for every basket.

Why this works · a little deeper

A node is one labelled step in the tree. Its count tells us how many baskets followed the whole path to that step. It is not always the total count of that item. That is why c has two nodes, with counts 3 and 1.

The first read through the original baskets finds the item counts and order. The second builds the tree. Links from the header let us find the same item on different branches. Gold marks show the most recently inserted path.

The tree saves space when many baskets start the same way. FP-growth uses it to find patterns without making an explicit candidate list. It is often efficient, but lots of branches and smaller follow-up trees can use plenty of memory. It is not always faster for every dataset.

Quick check · One c node says c:3. Does that mean c appears only three times overall?

No. Three baskets followed that path. A different branch has c:1. Across all five baskets, c appears four times.

The tree stores the baskets. Next, follow its paths to find patterns involving one chosen item.

Next: FP-growth follows a suffix ↓
12FP-growth follows a suffix

How do we find patterns that end with m?

Choose an item, such as m. We will find patterns where m comes last in the fixed item order. That ending is called the suffix. Find each m node and follow its path back towards the root. Keep the items before m and the count on that m node. This list of paths and counts is the conditional pattern base: the earlier items found with m.

Find patterns ending in m, with at least three matches

Conditional base for m:
f, c, a : weight 2
f, c, a, b : weight 1

Conditional counts: f:3, c:3, a:3, b:1
Remove b; conditional path is f:3 → c:3 → a:3

A weight is how many baskets a path stands for. The two m paths give f, c and a a count of 3 each, but b only 1. Drop b. Choose any combination of f, c and a, then add m. Including m by itself, this gives 8 patterns in the m projection. Here “projection” means the search focused on m and items earlier than m.

Source: Lecture pp.34–35; textbook §6.2.4. The example on this page stays the same when you change the interactive picture.

Why this works · a little deeper

The path f,c,a ends at an m node with count 2. Use that 2 as the path’s weight. Do not use f’s count of 4: some of those baskets never reached this m node.

Build a smaller FP-tree from these weighted paths. Remove items below the same minimum count used before. Repeat the process on that smaller tree. Repeating a procedure this way is called recursion. If the tree is just one path, list its item combinations directly. If it branches, more focused searches are needed.

This picture uses the complete five-basket tree. It does not use only the baskets you had inserted in the previous section. The label makes that difference clear.

We only use items earlier than the chosen suffix in the fixed order. A pattern with a later item is found when we search for that later ending. So choosing m does not show every pattern that contains m; it shows the patterns assigned to this m search.

Quick check · b appears three times overall, but only once in the m paths. Does b pass a count cutoff of 3 in this search?

No. We need three matches within these m paths. b has only one here, so it is removed from the smaller tree.

FP-growth reuses tree paths. Next, try a method that reuses lists of basket IDs.

Next: Eclat intersects transaction IDs ↓
13Eclat intersects transaction IDs

Can we find shared baskets by comparing their IDs?

Make a list of basket IDs for each item. Apple has {100, 300}. Coke has {100, 200, 300}. Keep only the IDs in both lists: {100, 300}. This is called an intersection. It gives the baskets with both items, so its size is their support count. Eclat finds bigger groups using these shared-ID lists.

Keep the basket IDs that appear in both lists

Apple: {100, 300}
Coke: {100, 200, 300}
Intersection: {100, 300}
count({Apple, Coke}) = 2

Why this works · a little deeper

We first read the baskets once to build the ID lists. This item-to-baskets view is called a vertical format. Later, we can compare the lists rather than read every original row again.

For three or more items, keep only IDs shared by all their lists. A list for Bread + Coke already contains only baskets with both. We can compare that list with Egg’s list to find Bread + Coke + Egg.

Long ID lists take memory and time to compare. A diffset is another option: record which IDs we lose when adding an item. Adding Coke to Apple loses no Apple basket IDs, so the diffset relative to Apple is empty.

Quick check · Apple has two basket IDs and Coke has three. Is their shared count 2 + 3?

No. Keep only IDs present in both lists. There are two: 100 and 300. Adding the counts would include baskets with only one item and count shared baskets twice.

We can now find many patterns. Next, see which ones we can keep without storing every smaller group.

Next: Frequent, closed, maximal ↓
14Frequent, closed, maximal

Can we keep fewer patterns without forgetting their counts?

A frequent group passes minimum support. It is closed if adding more items always lowers its count. It is maximal if adding more items always makes it fail minimum support. Closed groups, kept with their counts, let us recover every frequent group’s count. Maximal groups tell us which smaller groups are frequent, but can lose their exact counts.

Why this works · a little deeper

A bigger group containing all of X is a proper superset of X. Every maximal frequent group is closed. A closed group can still have a bigger frequent group; that bigger group just has a lower count.

Here A–D are item names in the seminar’s separate dataset. They are not our product abbreviations. A line in the diagram joins groups that differ by one added item and occur in this data.

To recover a frequent group X’s count, find the closed frequent groups that contain all of X. Take their highest count. This works when we keep all the closed frequent groups and their counts. Maximal groups let us identify frequent smaller groups, but usually cannot give their exact counts.

From one frequent group with 100 items, we can choose 2¹⁰⁰ − 1 nonempty groups, including the whole group itself. That is an enormous list. Special closed-pattern algorithms avoid listing everything first. They can merge items that always appear together, skip smaller groups with the same count, avoid repeated searches, and check directly whether a group is closed.

At 90% confidence, the seminar’s passing rules are A → C and B → C. The reverse rules C → A and C → B have confidence 2/3, so they fail the 90% cutoff.

Quick check · In the seminar example, is C closed? Is it maximal?

C is closed: no bigger group has its count of 3. It is not maximal: the bigger groups AC and BC still pass with count 2.

We know how to keep patterns and counts. Next, see what happens when we add baskets with neither item.

Next: Null transactions change some scores ↓
15Null transactions change some scores

What changes when we add baskets with neither item?

A null transaction is a basket with neither X nor Y. Adding these baskets makes the total N bigger. Support and lift change. But the baskets with X, with Y, or with both stay the same. So confidence stays the same in both directions.

A made-up example to isolate one change

Both = 10, X only = 10, Y only = 10
With 0 null rows: N=30, lift=0.75
With 10 null rows: N=40, lift=1.00
With 100 null rows: N=130, lift=3.25
In all three: conf(X→Y)=conf(Y→X)=0.50

These numbers are made up for teaching. We keep the baskets with either item exactly the same. We only add baskets with neither, so we can see which scores react to that change.

Why this works · a little deeper

A score is null-invariant if adding “neither” baskets does not change it, while all the other counts stay fixed. Confidence, all-confidence, max-confidence, Kulczynski, cosine and the imbalance ratio have this property.

Call the two directional confidences c₁ = P(Y|X) and c₂ = P(X|Y). All-confidence takes the smaller one: min(c₁,c₂). Max-confidence takes the larger one: max(c₁,c₂). Kulczynski, or Kulc, adds them and divides by two: (c₁+c₂)/2. Cosine multiplies them, then takes the square root: √(c₁c₂). A square root is a nonnegative number that gives the value inside when multiplied by itself. For example, √0.25 = 0.5 because 0.5 × 0.5 = 0.25. When these scores can be calculated, they range from 0 to 1.

IR = |count(X) − count(Y)|
/ [count(X)+count(Y)−count(X∪Y)]

The imbalance ratio, or IR, compares the sizes of the X and Y groups. The bars | | in the formula mean we use the size of the difference, ignoring its sign. The bottom counts baskets with at least one of X or Y. IR = 0 means the groups are the same size. A high IR warns that the two directional confidences may differ a lot. Kulc describes overlap; IR adds the group-size comparison.

Ignoring “neither” baskets is useful for some questions, but not every question. Lift compares against how common the items are across all baskets, so those extra baskets matter to it. The other scores ask different questions. Kulc = 0.5 does not by itself prove the items are independent.

Quick check · Does a basket with neither item count as a failed match in the X group?

No. It has no X, so it never joins the X group used for confidence. It does count in the total number of baskets used for support and baseline rates.

Changing the total changed our baseline. Next, compare actual counts with the counts we would expect.

Next: Observed versus expected ↓
16Observed versus expected

How do we compare actual counts with expected counts?

Observed is the count in our data. Expected is the count we would get if X and Y were independent, with the same group sizes. Pearson’s chi-square, written χ², compares all four groups: both, X only, Y only and neither. For each group, subtract expected from observed. Multiply that difference by itself, then divide by expected. Add the four answers to get χ².

Why this works · a little deeper

In a two-way table, each expected count is row total × column total ÷ N. For Games + videos, that is 6,000 × 7,500 ÷ 10,000 = 4,500. The little ² means “multiply by itself”, called squaring. The picture puts observed and expected counts on the same scale. The table shows how much each of the four groups adds to χ².

Squaring removes the sign, so χ² does not tell us whether the items appear together more or less than expected. Compare the observed and expected “both” counts to find that direction. More records can make χ² larger. Adding “neither” rows can also change it.

A large χ² does not finish a significance test by itself. A test also needs assumptions about how records were collected, a chosen false-alarm rate, and the right reference distribution. Degrees of freedom tells us which distribution to use. In the usual 2×2 case, where neither variable is constant, it is 1. A p-value tells us how often we would get a statistic at least this large under the independence model and the test assumptions. Searching many patterns may need an adjustment for extra false alarms. χ² > 1 is not a general passing rule. This notebook shows the uncorrected Pearson calculation; it does not calculate a p-value.

Quick check · Observed is below expected. Can its squared contribution to χ² be negative?

No. The difference is negative, but squaring it makes it nonnegative. To find the direction of the pattern, compare observed with expected before squaring.

Scores help us judge patterns. Next, add conditions that keep the search focused on what we need.

Next: Constraints direct the search ↓
17Constraints direct the search

When can we stop checking bigger groups?

A constraint is a condition a group must meet, such as “total cost at most 35”. If costs are all zero or positive, adding more items cannot fix an over-budget group. This is called anti-monotone: once it fails, bigger groups fail too. For “total cost at least 35”, adding items keeps a passing group passing. This is called monotone.

Why this works · a little deeper

If values are all zero or positive, sum(S) ≤ v is anti-monotone: once the total is too high, it stays too high. sum(S) ≥ v is monotone: once the target is reached, it stays reached. A negative value can lower the total, so these shortcuts are not valid without the nonnegative-value assumption.

The range is largest value − smallest value. Adding an item cannot make that range narrower. So an upper range limit is anti-monotone: once too wide, always too wide. A lower range target is monotone: once wide enough, always wide enough.

A succinct constraint lets us make only allowed items or groups before counting support. For example, “no price above 120” lets us remove each item priced above 120 at the start. This is written max(price) ≤ 120.

Some conditions gain a useful shortcut if we check items in a carefully chosen order. These are called convertible constraints. Average-value conditions are one example, but we must show why that order makes the shortcut valid. Inconvertible means we cannot make that kind of conversion for the values we allow. If sums can mix any positive and negative values, adding an item may turn a pass into a fail or a fail into a pass.

Use a valid condition early when it lets us skip work. Hiding unwanted patterns after the whole search is finished gives a shorter list, but does not save the work already done.

Quick check · A group costs 50. The budget is at most 35. Could adding an item worth −30 make it pass?

Yes. 50 − 30 = 20, which is below 35. That is why the “once over budget, always over budget” shortcut needs values that are not negative.

A budget condition controls one search. Next, see how broad and specific categories affect another.

Next: Categories have different levels ↓
18Categories have different levels

Why might a common category hide a less common type?

Every Skim milk basket is also a Milk basket. So Milk is at least as common as Skim milk. One support cutoff may keep the broad category and remove the specific type. A lower cutoff for specific types can reveal them. Remember that they are now passing a different minimum.

Why this works · a little deeper

A taxonomy is a category tree, such as Dairy → Milk → Skim milk. The broad category is the parent; the more specific type is a child. Searching at several levels is called multilevel association mining. Specific types often need lower support cutoffs because fewer baskets contain them.

A more specific rule may repeat what we already know. The lecture compares Milk → Wheat bread at 70% confidence with 2% milk → Wheat bread at 72%. The extra 2 percentage points may add little useful information. We also need to consider how common that milk type is.

Numbers can become items too. For example, an age band of 34–35 and an income band of 30–50K can form the left side of a rule about buying a TV. This is called quantitative association mining. Next, we will turn purchase amounts into named bands.

Quick check · Is Milk → Skim milk automatically a new discovery about shopping habits?

Why this works · a little deeper

For the small sample, the practical says ? means the item is absent, so we can use False. In another dataset, a missing value might mean “we do not know”. Do not turn “unknown” into “absent” without checking what it means.

pd.qcut makes bands with roughly equal numbers of records. It chooses boundaries from the data. pd.cut uses numeric boundaries we choose. If many values tie, qcut may try to make the same boundary more than once. We need to decide how to handle that case.

A token is a named item, such as Cat=1 or Purchase=High. The names keep category numbers separate from band labels. Cat=1 means category 1 appears in any category slot. If the slot itself matters, keep that in the name, such as Category_1=1.

The practical uses zero to mark an empty extra-category slot. It does not mean a product called category zero. We can choose to make absence an item, but it may produce many obvious rules. Each product row has just one purchase band, so Low and High cannot both be True in the same row.

Next: A small Python workflow ↓
20A small Python workflow

What does the Python code do, step by step?

Return to our four shopping baskets. The code has three steps: make the yes/no table, find frequent itemsets, then make rules. Apriori and FP-growth should give the same results for the same data and cutoffs. They find the groups in different ways, but the counts and confidence calculations are the same.

A complete Python example using the four baskets

To run this example, install its two libraries in your Python environment: python3 -m pip install pandas mlxtend. Then copy the code below, or download the companion script.

import pandas as pd
from mlxtend.frequent_patterns import (
    apriori, association_rules)

# 1. Presence rows, without transaction IDs
encoded = pd.DataFrame([
    [1, 0, 1, 1, 0],  # basket 100
    [0, 1, 1, 0, 1],  # basket 200
    [1, 1, 1, 0, 1],  # basket 300
    [0, 1, 0, 0, 1],  # basket 400
], columns=["Apple", "Bread", "Coke",
            "DVD", "Egg"], dtype=bool)

# 2. Itemsets with at least 50% support
freq = apriori(encoded,
    min_support=0.5, use_colnames=True)

# 3. Rules with at least 90% confidence
rules = association_rules(freq,
    metric="confidence", min_threshold=0.9,
    num_itemsets=len(encoded))
rules = rules.sort_values("lift", ascending=False)
print(len(freq), len(rules))  # 9 5

encoded is the yes/no table. freq stores the frequent groups and their support. rules stores the arrows and scores. The code prints 9 5: nine frequent groups and five passing rules. This printed example uses the original baskets. The interactive picture uses your current edits.

Here is how to read the code. import loads a tool. The name before = stores a result. Each inner list is one basket row. columns gives the product names. dtype=bool turns 1/0 into True/False. Why this works · a little deeper

An actionable rule suggests a useful decision to consider. A trivial rule repeats something we already know, such as a category link. An inexplicable rule is hard to explain. It may need investigation before we know whether it helps.

A rare pair can have high lift even when only a few records contain both. Always look at the actual count too. Does the pattern appear in a later period? Did we search so many rules that some could look interesting by chance? Did our item definitions create the link automatically?
