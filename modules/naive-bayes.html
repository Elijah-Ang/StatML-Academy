Stage 01 · Observe

From clues to a class

Imagine an email filter deciding between Spam and Ham, meaning ordinary mail. It sees clues such as whether an email contains “free”, “meeting”, or “urgent”.

For every possible class, Naive Bayes asks: How common was this class before the new email? And how compatible are these clues with that class?

Model output

The model produces one score per class. The largest score becomes the prediction, and the scores can be normalised into posterior probabilities.

SpamHamEvidence
Naive Bayes is a generative classifier: it models how features are distributed inside each class, then uses those class models to classify new rows.
Stage 02 · Understand

Restrict the group first

Conditional probability means probability after restricting attention to a particular group.

P(Free = Yes | Spam) = spam emails containing “free” ÷ all spam emails = 30 ÷ 40 = 0.75

The vertical bar means “given”. We enter the Spam group first, then count how many of those messages contain “free”.

Do not reverse the condition. P(Free | Spam) and P(Spam | Free) ask different questions, despite the long human campaign to treat them as interchangeable.
Quick check

12 of 60 ham emails contain “urgent”. Therefore:

P(Urgent = Yes | Ham) = 12 ÷ 60 = 0.20
Stage 03 · Formalise

Bayes updates a prior belief

P(Class | Evidence) = P(Evidence | Class) × P(Class) ÷ P(Evidence)
Prior P(Class)
Belief before seeing this row’s evidence.
Likelihood P(Evidence | Class)
Compatibility of the evidence with that class.
Evidence P(Evidence)
The normalising constant shared by all classes.
Posterior P(Class | Evidence)
Updated belief after seeing the evidence.

When only the winning class matters, the denominator is shared, so the classifier can compare unnormalised class scores.

P(Class | Evidence) ∝ P(Class) × P(Evidence | Class)
Stage 04 · Question

Why is it called “naive”?

A complete likelihood for several features could require a large table covering every combination of “free”, “meeting”, and “urgent”.

Naive Bayes replaces that complicated joint likelihood with a product of separate feature likelihoods.

P(x₁, x₂, …, xₚ | Class) ≈ P(x₁ | Class) × P(x₂ | Class) × … × P(xₚ | Class)
Conditional independence claim

Once the class is known, learning one feature is assumed to tell us nothing extra about another feature.

Within SpamFree ⟂ UrgentWithin Ham
The assumption is often false. Yet the ordering of class scores can still be useful even when the resulting probabilities are imperfect.
Stage 05 · Fit

Begin with class priors

Suppose the training set contains 40 spam emails and 60 ham emails. Before any words are inspected, the empirical class frequencies become the priors.

0.40
P(Spam) = 40 / 100
0.60
P(Ham) = 60 / 100
Priors need not always equal raw training frequencies. Domain knowledge, sampling design, or expected deployment prevalence may justify adjusted priors, but the choice should be documented.
A training set balanced to 50/50 can mislead when production traffic is only 5% spam. Sampling convenience is not deployment reality.
Stage 06 · Fit

Then count feature likelihoods

For binary clues, estimate both presence and absence inside each class. A Bernoulli Naive Bayes model uses all of those terms.

FeatureYes | SpamNo | SpamYes | HamNo | Ham
Free30/4010/403/6057/60
Meeting4/4036/4045/6015/60

Training is mostly counting. The model stores priors and class-conditional feature parameters. It does not need gradient descent.

A multinomial text model uses token counts instead, so the right likelihood model depends on how the features are represented.

Stage 07 · Predict

Multiply the evidence

Consider an email where Free = Yes, Meeting = No, and Urgent = Yes.

Spam score = P(Spam) × P(Free=Y | Spam) × P(Meeting=N | Spam) × P(Urgent=Y | Spam) Ham score = P(Ham) × P(Free=Y | Ham) × P(Meeting=N | Ham) × P(Urgent=Y | Ham)

The larger score wins. To obtain probabilities, divide each score by the total score across classes.

P(Spam | x) = Spam score ÷ (Spam score + Ham score)
A clue helps a class only when that clue is more likely under that class than under competitors. Clues common to every class contribute little discrimination.
Stage 08 · Safeguard

Zero counts can erase a class

Suppose no spam email in training contained “invoice”. The unsmoothed estimate is P(Invoice = Yes | Spam) = 0.

Complete Spam score = prior × … × 0 × … = 0

One unseen combination now destroys all the other evidence. For a finite sample, that confidence is usually absurdly strong.

Smoothed probability = (count + α) ÷ (class count + α × categories)
α = 0
Unseen events remain impossible
α > 0
Reserve probability for unseen events
Laplace smoothing uses α = 1. Smaller positive values are often called Lidstone smoothing. Tune α on validation data, never on the final test set.
Stage 09 · Compute

Add logs, not tiny products

With thousands of features, multiplying many probabilities can produce numbers so tiny that a computer rounds them to zero. This is numerical underflow.

log score(Class) = log P(Class) + Σⱼ log P(xⱼ | Class)

The logarithm turns multiplication into addition. Because log is monotonic, the largest product is also the largest log score.

0.4 × 0.01 × 0.0002 × …
Probability space
log 0.4 + log 0.01 + …
Log space
Practical implementations normalise log scores with a stable log-sum-exp calculation rather than exponentiating huge negative values naively.
Stage 10 · Extend

Gaussian NB handles measurements

For a continuous feature such as temperature, Gaussian Naive Bayes assumes the values inside each class follow a normal bell-shaped distribution.

P(xⱼ | Class = c) = Normal density with mean μⱼc and variance σ²ⱼc
ClassMean temperatureStandard deviation
Buy ice cream29°C3°C
Do not buy19°C4°C
The assumption is class-conditional and feature-specific. Strong skew, heavy tails, multimodality, or near-zero variance can make the density model poor.
Stage 11 · Choose

Match the variant to the features

The model name matters less than the feature story. Ask what distribution the representation implies.

Gaussian NBContinuous measurements modelled with Gaussian densities.
Multinomial NBNon-negative counts or count-like weights, such as word counts.
Bernoulli NBBinary presence or absence features.
Categorical NBEach feature takes one category, such as colour or browser type.
Complement NBCount data scored with complementary-class statistics, often for imbalanced text.
If an email is represented by how many times each word appears, the classic match is Multinomial Naive Bayes.
Stage 12 · Diagnose

Correlated clues get double-counted

“Contains free” and “contains free offer” are highly related. Naive Bayes may treat them as two independent pieces of evidence and push the posterior too far.

Repeated or correlated clues → duplicated likelihood evidence → posterior too extreme

The predicted class can remain correct because the score ordering survives, while the reported probability fails to match real frequencies.

Separate two kinds of quality
Class
Was the winning label correct?
Probability
Does 80% happen about 80% of the time?
Remove obvious duplicates, compare with discriminative models such as logistic regression, and calibrate on held-out data when probabilities drive decisions.
Stage 13 · Evaluate

Test decisions, rankings, and probabilities

An evaluation plan should match how the predictions will be used.

Accuracy / F1Quality of hard class decisions.
ROC-AUC / PR-AUCRanking quality across thresholds.
Log lossRewards accurate probabilities and punishes confident errors.
Calibration curveChecks whether predicted probabilities match observed frequencies.
Leakage warning: vocabulary creation, category encoding, feature selection, imputation, and smoothing choices must be fitted within each training split.
Accuracy can hide failure on a rare class. Inspect per-class recall, precision-recall curves, and a confusion matrix.
Stage 14 · Deploy

Plan for awkward reality

Multiclass prediction simply computes one prior-plus-likelihood score per class. Normalised posteriors should sum to one across all classes.

Fit preprocessing only on training data.
Estimate priors and likelihood parameters.
Score validation rows in log space.
Select variant, smoothing, and thresholds.
Freeze the pipeline.
Measure drift and calibration after deployment.
Operational edge cases

Unseen category: use smoothing and an encoding strategy for unknown values.

Missing feature: model missingness explicitly or omit its likelihood under a justified strategy.

Changing prevalence: monitor priors, then recalibrate or refit.

Decision threshold: choose from costs and validation data, not automatically 0.5.

Key takeaways
✓

Combine a class prior with class-conditional feature likelihoods.

✓

Factorise the joint likelihood into separate feature terms under the “naive” assumption.

✓

Use smoothing to stop unseen combinations from forcing a class score to zero.

✓

✓

Final concept: Naive Bayes can classify well even when independence is false because the approximation may still preserve the correct ordering of class scores, though calibration can suffer.
