Data Leakage & Pipelines

Keep validation, test, group, and future information out of model development.

PrerequisitesBasic supervised learning
Recommended nextEvaluation Metrics or Model Selection

Stage 01

The problem

A model can appear excellent because information crossed the boundary between development and evaluation. Leakage estimates performance for a procedure that cannot exist in deployment.

Stage 02

Intuition and objective

Treat the pipeline—not only the final algorithm—as the model. Anything that learns a mean, category frequency, component, selected feature, threshold, or synthetic observation must learn it inside each training fold.

Stage 03

Worked example

Suppose missing ages are filled with the mean of all 1,000 rows and then five-fold CV is run. Every validation fold has influenced its own imputed values. The honest workflow fits five separate imputers, each on that fold’s 800 training rows, and applies it to the 200 held-out rows.

Stage 04

Reasoning with the method

Leakage can enter through features, rows, groups, time or repeated comparison. A post-outcome billing code is feature leakage; duplicate images across folds are row leakage; tomorrow’s rolling average is time leakage; repeatedly checking the same test score creates selection leakage. Nested cross-validation separates inner model selection from outer evaluation. Target encoding, oversampling, outlier rules, feature selection, PCA and threshold selection are all estimators. Each must be re-learned within every training fold. The decisive audit question is whether a value, rule or analyst decision could have known anything about the held-out outcome.

A defensible analysis connects the mathematical target to the real decision. Identify what is estimated, which observations contribute independent information, what choices are learned from data, and which uncertainty remains after fitting. Then ask how the conclusion would change under another reasonable sample, a plausible alternative specification, or a shift in the deployment population. This reasoning must happen before the final test set is opened. The test result evaluates the locked procedure; it does not choose that procedure. Sensitivity analysis is most useful when it is planned around credible failure modes rather than used to search for a preferred answer.

Stage 05

Interactive laboratory

Classify each pipeline as safe or leaking. Feedback identifies exactly where information crosses the boundary.

Stage 06

Assumptions and failure modes

Assumptions

The split must match the unit of independence and deployment timing. Features must exist at the moment a prediction is made.

When the method fails

Random CV fails for time order, repeated patients, households, organisations, duplicated rows, and target-derived features. Oversampling before CV creates near-duplicates across folds.

Stage 07

Practical workflow

  1. Define prediction time and independent unit
  2. Reserve the final test set
  3. Choose stratified, grouped, time-series, or nested resampling
  4. Fit every learned transform inside training folds
  5. Lock and evaluate once

Stage 08

Interpretation and reporting

What to report: Document split units, dates or groups, pipeline order, cross-validation variant, test isolation and every target-aware transformation.

Common misuse: Preprocessing the full dataset before splitting because “it is not the model.”

Stage 09

Knowledge checks

Which workflow leaks?

Answer and explanation

Scale all rows, then cross-validate. Scaling all rows lets each validation fold influence its own transformation.

Where should oversampling happen?

Answer and explanation

Inside each training fold. Oversampling must not create synthetic or duplicated information across held-out boundaries.

Repeated visits from each patient require…

Answer and explanation

Grouped CV by patient. All visits from one patient belong in the same fold.

For forecasting, use…

Answer and explanation

Time-ordered validation. Every validation observation must occur after the observations used to fit it.

What is target leakage?

Answer and explanation

Using information unavailable at prediction time that reveals the outcome. Availability at the real prediction moment is the key test.
