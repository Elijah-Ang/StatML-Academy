Stage 01

The Raw Data

Every machine learning model starts with data. Here we have measurements of fruits — each one scored on Sweetness and Color Intensity.

Each fruit is already labeled: it's either an Apple or an Orange. Because we have labels, this is supervised learning.

💡 Supervised learning means the model learns from examples where the answer is already known. Here, each fruit already has a known label: Apple or Orange. Later, KNN uses these known examples as its "memory" to classify any new, unknown fruit.

The Whole Idea of KNN

KNN stands for K-Nearest Neighbors. The concept is incredibly straightforward:

To classify a new unknown item, look at the K closest known examples (neighbors) in your dataset. Then, simply copy the label that appears most often among those neighbors!

Example: If we want to identify a mystery fruit, and its 3 closest neighbors are 🍎, 🍎, and 🍊, then Apple gets 2 votes and Orange gets 1 vote. KNN predicts Apple.

New unknown fruit → Find closest old fruits → Count their labels → Predict majority label

Tiny ML Dictionary

Before moving forward, let's establish a few basic terms:

• Feature: A measurement used to make a prediction (e.g., Sweetness or Color Intensity).
• Label: The correct answer already known for our examples (e.g., Apple or Orange).
• Class: The category we are trying to predict (e.g., Apple class vs. Orange class).
• Query Point: The new, unknown item we want to classify. In our visual plots, the query point is represented by a star ★.

"We know the query point's features, but we do not know its label yet. KNN tries to guess the label based on its neighbors."

Training Dataset

💡 KNN needs labeled examples to learn from. It doesn't build a formula — it simply remembers all the data and compares new points to what it already knows.

Stage 02

Choosing Good Features

Not every measurement helps separate classes. We pick features where the groups actually differ — like Sweetness and Color Intensity.

Bad features (random IDs, row numbers) add noise without signal. KNN is especially sensitive to irrelevant features because they pollute the distance calculation.

Why Feature Selection Matters

A good feature helps separate the classes clearly. A bad feature adds confusion and distorts the distance between points.

Useful Examples:

  • Sweetness helps because apples and oranges have different natural sweetness profiles.
  • Color Intensity helps separate reddish apples from yellowish-orange citrus fruits.

Not Useful Examples:

  • Row number is just the order in the table; it contains zero predictive power.
  • Day picked is unrelated to fruit sweetness or species and would only add noise.

Feature Quality

✅ Sweetness — The two fruit groups show different sweetness patterns
✅ Color Intensity — Apples score higher on red
❌ Row number — meaningless for prediction
❌ Day picked — no predictive power

💡 Notice how the two classes form somewhat distinct clusters on the plot — a good sign. KNN relies entirely on spatial proximity.

Stage 03

Train / Test Split

We hold out a small test set (2 apples + 2 oranges) that the model will not see during training. The remaining points are used as the "memory" KNN will search through.

Testing on training data is one of the most common mistakes — it gives inflated confidence. A model that memorizes isn't smart; it's just a parrot.

Training vs. Testing Sets

• Training Set: The collection of examples KNN is allowed to remember and search through. This is the model's "memory".
• Test Set: Hidden examples set aside from the beginning, used ONLY at the very end to check if the model can accurately classify new, unseen data.

⚠️ Critical Warning (Data Leakage): Do not use the test set to choose K or tune features. If the model is exposed to the test set during its construction, your evaluation results are no longer honest. This is called data leakage!

Stage 04

Feature Scaling

This is the most common mistake with KNN. If Sweetness ranges 0–10 but Color ranges 0–100, the Color feature would completely dominate distance calculations.

We use Min-Max Scaling to squish every feature into the 0–1 range, giving each feature equal voice.

Scaled Value = (Value − Min) ÷ (Max − Min) Example: Sweetness = 7, Min = 2, Max = 9 Scaled Value = (7 − 2) ÷ (9 − 2) = 5 ÷ 7 ≈ 0.71

Important: Scale Using Training Data Only

To prevent data leakage, we calculate the Minimum and Maximum values using only the training set. We then use this exact same scale factor for training, test, and any future query points.

Training Data finds Min/Max ➔ same Min/Max scales training, test, and new query points

If we used the test set to calculate the scale range, information from the test set would leak into the training process, leading to over-optimistic performance estimates.

Stage 05

Measuring Distance

KNN's entire logic boils down to one question: "Who lives closest to me?" To answer that, we need a way to measure distance between points.

The most common choice is Euclidean distance — the straight-line distance between two points.

d(a, b) = √[(x₂ − x₁)² + (y₂ − y₁)²] This is just the Pythagorean theorem — the same formula you learned in geometry class.

What Does Distance Mean Here?

In machine learning, distance represents dissimilarity between items:

  • Short distance means high similarity. The items have very similar features.
  • Long distance means high difference. The items are very dissimilar.

Step-by-Step Distance Calculation:

Let's calculate the distance between our mystery fruit and a training fruit manually:

Query point (Mystery Fruit ★):
Sweetness = 0.45, Color = 0.55

Training point (Known Fruit):
Sweetness = 0.50, Color = 0.65

Euclidean Distance Formula:
d = √[(0.50 − 0.45)² + (0.65 − 0.55)²]
d = √[(0.05)² + (0.10)²]
d = √[0.0025 + 0.0100]
d = √0.0125
d ≈ 0.1118 (the straight-line distance)

Note: While Euclidean distance is the straight-line default, other metrics exist (e.g., Manhattan distance, which calculates distance along grid paths like city streets). This page uses Euclidean distance.

Stage 06

Choosing K

K is one of the most important hyperparameters in KNN — the number of neighbors to consult before making a prediction.

Small K (e.g. K=1): Very sensitive to noise. One outlier can flip the prediction.
Large K (e.g. K=15): Too smooth. Local patterns get drowned out by distant voters.

We do not just guess K blindly. Later, in Stage 12, we compare several K values using cross-validation and look for a sensible choice.

Who Chooses K?

K is a hyperparameter. In machine learning, a hyperparameter is a setting chosen by the human designer before the model starts predicting, rather than learned automatically from training data.

The Trade-Off:

  • Too Small K (e.g., K=1): Extremely sensitive to outliers and noise. The model may overfit (memorize noise as pattern).
  • Too Large K (e.g., K=15): Overly smooth and generic. Local patterns are drowned out by far-away votes. The model may underfit (miss the actual pattern).

How a Machine Learning Task is Configured:

Component Who Decides? Meaning
Features Human / Designer Measurements selected to describe items (e.g., Sweetness)
Scaling Method Human choice How feature ranges are made comparable (e.g., Min-Max)
Distance Metric Human choice Mathematical formula to measure closeness (e.g., Euclidean)
K value Human choice Number of neighboring votes allowed to participate
Training labels Existing Data The ground-truth answers for old examples
Prediction KNN vote rule Majority vote among the K closest neighbors

Stage 08

The Majority Vote

Classification is now a democracy. Each of the K nearest neighbors gets one vote. The class with the most votes wins.

Equal Vote Democracy

In standard KNN, each neighbor inside the K-limit gets exactly one equal vote. The category with the highest vote count wins the prediction.

⚠️ Note: Vote share is not probability! If K=3 and Apples win 2-1, this does not mean the fruit has a 66.7% probability of being an Apple. It only means 2 of the 3 nearest examples in our training memory were apples. Do not confuse vote tally with actual likelihood!

Why odd numbers for K?

In two-class (binary) classification, choosing an odd K guarantees there will be no ties. If we used an even number (like K=4) and got 2 Apple votes and 2 Orange votes, the model would require a complex, arbitrary tie-breaking rule. Using odd K values elegantly prevents this!

Stage 09

Decision Boundary

What if we classified every possible point on the plot? The result is a colorful map showing which regions belong to which class.

Unlike linear models, KNN boundaries are non-linear — they bend and curve around the data naturally. The boundary is just wherever the majority vote flips from one class to the other.

What is a Decision Boundary?

A Decision Boundary is the invisible dividing line or contour across the feature space where the model switches from predicting one class to another. Any point that falls on one side is predicted as Apple; any point on the other is Orange.

• Non-parametric: KNN has no underlying assumptions or mathematical weights to fit (unlike linear equations). The boundary adapts organically to the data density.
• Bias-Variance Tradeoff: Adjusting K alters this boundary:
K = 1 (High Variance / Low Bias):

Extremely flexible, wiggly, and complex boundary. It fits every outlier precisely, memorizing noise and likely overfitting.

Medium K (Balanced Tradeoff):

Smooth, reasonable boundary shapes that filter out minor noise while preserving genuine group clusters.

Large K (Low Variance / High Bias):

Highly smooth, almost straight boundaries. It ignores localized trends completely, risking underfitting.

Boundary Properties

The decision boundary emerges organically from the data — no formula is fitted. This is what makes KNN a non-parametric model.

💡 Small K = wiggly, complex boundaries. Large K = smoother boundaries. This is the classic bias-variance tradeoff.

Stage 12

The Effect of K

K is one of the most important tuning knobs. Watch how the decision boundary changes as K increases.

What is Leave-One-Out Cross-Validation (LOOCV)?

To choose the optimal value of K honestly, we cannot test different values on our final held-out test set (as that would leak information). Instead, we perform cross-validation inside our training set only.

The Leave-One-Out Recipe:

  1. Select one point from the training set and "hide" it.
  2. Treat the remaining training points as the model's memory.
  3. Use KNN with a specific K to predict the label of the hidden point.
  4. Record whether the prediction was correct.
  5. Repeat this sequence until every single training point has had a turn being hidden.
  6. Calculate the average accuracy across all attempts.
Training set only ➔ Try K values (1 to 15) ➔ CV accuracy ➔ Choose optimal K ➔ Final test set used ONCE

⚠️ Rule of thumb: Do NOT select your hyperparameters using the final test set. If you test multiple K values on the test set and pick the one with highest accuracy, your test set is no longer an independent evaluator!

The Elbow / Knee Method for Choosing K

For KNN, we usually choose K using validation or cross-validation performance. We can plot K against validation accuracy or validation error. Sometimes we look for an elbow or knee point: a place where increasing K no longer improves performance much. This is an elbow-style validation curve, not the K-means inertia elbow method. Here, the y-axis is cross-validation accuracy, not clustering inertia.

Simple Hypothetical Example of Knee Selection:
• K = 1: 75% accuracy, noisy and overfit.
• K = 3: 88% accuracy, big improvement.
• K = 5: 92% accuracy, smaller improvement.
• K = 7: 92% accuracy, no real improvement.
➔ Clear interpretation: K = 5 is the clearest knee because accuracy improves up to K = 5, then barely improves after that. K = 3 may still be acceptable if you want a smaller-neighbor model, but K = 5 is the cleaner elbow-style choice in this example.

Stage 13

Strengths and Weaknesses

Before using K-Nearest Neighbors in practice, it is vital to know when it shines and where it struggles.

💪 Strengths

  • Simple to understand: Intuitive to explain to stakeholders.
  • No Parameter-Learning Phase: KNN does not fit weights or coefficients. It stores the training examples and uses them during prediction.
  • Highly Flexible: Can easily construct complex, non-linear decision boundaries.
  • Naturally Multi-class: Works seamlessly for predicting 3 or more classes.

⚠️ Weaknesses & Limitations

  • Sensitive to Scale: Requires mandatory feature scaling; otherwise, features with larger ranges dominate.
  • The Curse of Dimensionality: When there are too many features, distance often becomes less useful because many points start to seem similarly far apart. This makes it harder for KNN to find truly meaningful neighbors.
  • Slow at Scale: Must calculate distance to every single stored point for every new query. High memory and computing costs.
  • Class Imbalance: If you have 95% Apples and 5% Oranges, votes will naturally skew heavily to Apple.

The Whole Story in Plain English

Here is the complete machine learning workflow we walked through today:

  1. Labeled Examples: Start with known data (fruits with known categories).
  2. Feature Selection: Select high-quality, relevant properties (sweetness, color).
  3. Train/Test Split: Set aside a final held-out test set to keep final evaluation fair.
  4. Feature Scaling: Force all scales to 0–1 so distance checks remain unbiased.
  5. Mystery Input: Introduce an unknown query point (★) on the plot.
  6. Distance Measuring: Run Euclidean distance against all stored training examples.
  7. Hyperparameter K: Choose K (the count of voting neighbors).
  8. Locate Neighbors: Gather the K nearest samples.
  9. Tally Votes: Perform a democratic, equal-weight majority vote.
  10. Predict: Assign the winning class to the unknown query point.
  11. Independent Testing: Run the held-out test points to check the model's accuracy.
  12. Evaluate Quality: Read the confusion matrix, recall, precision, and F1 metrics.
  13. Tune K: Use cross-validation inside the training memory to find the best K.
  14. Analyze Trade-offs: Know KNN's limits, such as scale sensitivity and the curse of dimensionality.
