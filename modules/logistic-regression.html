What is probability? 🤔

Probability means "how likely something is to happen." It is always written as a number between 0 and 1:

  • 0 means impossible (0% chance).
  • 0.5 means 50-50 (50% chance).
  • 1 means certain (100% chance).

In this guide, probability means: "How likely is someone to buy ice cream?"

Bought = 1 and Didn't buy = 0 are just category labels. They do not mean someone bought one ice cream or zero ice creams. They simply mark the two possible outcomes for the model.

Notice how higher temperatures tend to cluster near y = 1? That's the signal our model will learn to capture.

📌 This is a small toy dataset with 20 rows designed for teaching. Real datasets have hundreds or thousands of rows.

Stage 02

Why Lines Break 📏

Your first instinct might be to draw a straight line through the data — that's linear regression.

But watch what happens: the line predicts values above 1 and below 0. Those aren't valid probabilities!

ŷ = b₀ + b₁ · Temperature Can give 1.5 or −0.3 … not a probability!

Why Bounds Matter 🚧

A probability cannot be below 0 or above 1:

  • Below 0 would mean “less than impossible.”
  • Above 1 would mean “more than certain.”

So a prediction like 1.5 means 150%, which makes no real-world sense. We need a curve that stays strictly between 0 and 1.

We need a function that squishes any number into the 0–1 range. Enter the sigmoid.

Stage 03

From a Raw Score to a Probability ✨

First, logistic regression starts the same way linear regression does. For each data point, one linear equation combines that point's features with the model's learned weights and produces one raw number, called z.

z = b₀ + b₁x₁ + b₂x₂ + ··· one data point → one raw score z

z is not a z-score or a standard score. It is not learned separately for each point. It is simply the model's raw opinion before that opinion becomes a probability. z can be any number from negative infinity to positive infinity. If z = 0, the model is exactly at 50/50.

Only after that do we apply the sigmoid function to turn z into a probability between 0 and 1.

p = 1 / (1 + e⁻ᶻ) Large positive z → probability near 1 Large negative z → probability near 0 z = 0 → probability exactly 0.5

Stage 04

Weighted Clues 🧠

How do we construct the score z? Think of our features (Temperature, Sunny, Weekend) as clues. The model assigns a weight to each clue depending on its relative importance:

• A positive weight pushes the score toward "Buy" (y = 1).
• A negative weight pushes the score toward "Don't Buy" (y = 0).
• The final raw score z is the total combined push from all clues. The Sigmoid then turns this raw score into a clean final probability.

These sliders are a sandbox. You are manually changing the weights only to see how the mathematical curve reacts. In real training, the model learns these weights automatically by reducing log loss.

Stage 05 (Machine Learning):

The model adjusts weights automatically using gradient descent.

z = b₀ + b₁·standardized Temp + b₂·Sunny + b₃·Weekend

b₀ = bias (baseline push) · b₁, b₂, b₃ = individual clue pushes

Standardized temperature means we convert raw temperature values into a scaled version with a mean of 0 and standard deviation of 1. This keeps large temperature numbers from overpowering the smaller binary (0/1) features like Sunny and Weekend, helping gradient descent behave more smoothly during training.

Stage 05

Learning from Mistakes ⚙️

The model starts with initial weights, makes predictions, measures how wrong it was using log loss, then nudges the weights to improve. This is gradient descent.

Training does not directly choose z. Training learns better weights. Once the weights improve, the model calculates better z values for each row of data automatically:

Training updates weights → weights calculate z → sigmoid turns z into probability → threshold turns probability into Yes/No
L = −[ y·log(p) + (1−y)·log(1−p) ] The model is punished more when it's very confident but very wrong.

How Log Loss Thinks 🧠

Log loss measures the penalty of wrong answers. If the actual answer is 1 (Bought):

Real Answer Predicted Prob Meaning Loss Penalty
1 (Bought) 0.95 Confident & correct Small Loss (0.05)
1 (Bought) 0.55 Unsure but leaning right Medium Loss (0.60)
1 (Bought) 0.05 Confident & wrong! Huge Loss (3.00)

* Note: These loss values are examples for one single prediction. The training loss shown below is the average loss across all training rows.

Gradient descent is like adjusting a recipe little by little. If the model is wrong, it changes the weights in the direction that reduces loss. The learning rate controls how big each adjustment step is. Gradient descent is one teaching-friendly optimiser, not the definition of logistic regression: Newton, quasi-Newton, coordinate-descent and other solvers are also common. Feature scaling often improves numerical optimisation and is especially relevant with regularisation; fit scaling inside training folds.

⚠️ Warning on Learning Rate:
• Too small: Learning is very slow, requiring thousands of steps.
• Too large: The model may jump right over the best values and fail to settle.

Stage 06

Drawing the Line 🚦

The sigmoid gives a probability. But we need a decision: Yes or No. We pick a threshold.

If p ≥ threshold → predict Yes (1)
If p < threshold → predict No (0)

The model only gives probabilities. The threshold is a decision rule chosen by humans. We choose it based on what kind of mistake is worse or more costly for our specific situation:

Threshold vs. Probability 🔍

The threshold does not change the probability itself. It only changes how we convert that probability into a final Yes/No decision.

Example: If the model predicts a probability of 0.62:
• At threshold 0.50 → predict Yes (since 0.62 ≥ 0.50)
• At threshold 0.70 → predict No (since 0.62 < 0.70)

The probability stayed exactly 0.62. Only the decision rule changed.

Lowering the Threshold (e.g., 0.30):

Predicts "Yes" more easily. You catch more real buyers (high recall), but you also create more false alarms (false positives).

Raising the Threshold (e.g., 0.70):

Predicts "Yes" only when highly confident. You reduce false alarms (high precision), but you might miss many real buyers (false negatives).

Set Threshold

0.50

Select this threshold on validation data, never the final test set. Use error costs, prevalence, capacity, and the real objective. Lock the threshold with all preprocessing and calibration choices, then report final test performance once. Probability calibration and classification accuracy answer different questions.

Select the Decision Rule on Validation Data 📊

Use the validation set to explore threshold-dependent trade-offs. The final test set remains hidden while the threshold, metrics and model choices are still changing.

Every validation prediction falls into one of four boxes:

• TP (True Positive): Predicted Bought, and they really bought. Correct prediction!
• TN (True Negative): Predicted Didn't buy, and they did not buy. Correct prediction!
• FP (False Positive): Predicted Bought, but they did not buy. (False alarm!).
• FN (False Negative): Predicted Didn't buy, but they actually bought. (Missed buyer!).

Validation Metrics

Overall Accuracy --
Formula: (TP + TN) / (TP + TN + FP + FN)

Meaning: How often was the model correct overall? Best used when mistakes are equally costly.

Precision (Reliability of Yes Predictions) --
Formula: TP / (TP + FP)

Meaning: When the model predicts Bought, how often is it right? Critical when false alarms (FP) are expensive.

Recall (Sensitivity / Detection Rate) --
Formula: TP / (TP + FN)

Meaning: Out of all real positive buyers, how many did the model catch? Critical when missing a real positive (FN) is costly.

F1-Score --
Formula: 2 × (Precision × Recall) / (Precision + Recall)

Meaning: F1 is a balance score between precision and recall. It is not a normal average; it gives a low score if either precision or recall is weak. Perfect when you want to look at general model balance.

Stage 08

The Validation ROC Curve 🔔

The validation ROC curve shows: at every possible threshold, how does recall trade off against false-alarm rate? It is a development visual and never reads the final test set.

Think of a smoke alarm: too sensitive and it goes off when you cook toast; too lenient and it misses an actual fire.

Accuracy vs. ROC / AUC:

• Accuracy shows model performance at a single chosen threshold (like 0.50).

• ROC shows performance trade-offs across all possible thresholds.

• AUC (Area Under Curve) is not the same as accuracy. AUC summarizes how well the model separates/ranks positive cases from negative cases across all thresholds.

Key ROC Metrics Explained

An ROC curve plots two key metrics against each other at all possible thresholds from 0.0 to 1.0:

True Positive Rate (TPR / Recall): TP / (TP + FN)
Meaning: Out of all real buyers, what percentage did we catch? (Higher is better!)
False Positive Rate (FPR / False Alarm Rate): FP / (FP + TN)
Meaning: Out of all non-buyers, what percentage did we wrongly predict as buyers? (Lower is better!)

The ROC curve checks many possible thresholds, not just 0.5. Each point on the curve comes from a specific threshold value. Moving the threshold changes TPR and FPR.

—
AUC (Area Under Curve)

• AUC = 1.0: Perfect separation on this dataset.
• AUC = 0.5: Random guessing. The model has no predictive strength.
Note: AUC does not mean the model is perfect forever. It only summarizes separation performance on the data being evaluated.

📌 Note: Because this teaching example has a very small validation set, the ROC curve looks coarse and jumpy. With a larger validation sample, the curve would usually be smoother.

Stage 09

What the Numbers Mean 📎

We often want to know how the model estimates each feature (temperature, sunny day, weekend status) is associated with higher or lower predicted odds, while holding other features constant. Logistic regression gives us weights that can be converted into Odds Ratios.

Probability vs. Odds 🎲

Probability and Odds are related but express likelihood differently:

• Probability (p) asks: "Out of all outcomes, how likely is Yes?" (Varies between 0 and 1).
• Odds asks: "How much does the chance of Yes beat No?" (Varies from 0 to infinity). Formula: Odds = p / (1 - p)

Probability (p) Odds Formula Odds Value Meaning
0.50 (50%) 0.50 / 0.50 1 to 1 (1.0) Yes and No are equally likely
0.75 (75%) 0.75 / 0.25 3 to 1 (3.0) Yes is three times as likely as No
0.80 (80%) 0.80 / 0.20 4 to 1 (4.0) Yes is four times as likely as No

Taking the exponent of a weight (eweight) gives us the Odds Ratio (OR). This ratio tells us how the odds of buying are multiplied for each unit increase in that feature.

⚠️ Beginner Warning:
Odds are not the same as probability. An odds ratio of 2 does not mean the probability doubles! It means the odds ratio doubles (e.g. from 1:1 odds to 2:1 odds).

⚠️ Coefficient ≠ proof of cause:
A positive coefficient means the feature is associated with higher predicted probability in this model. It does not prove that modifying the feature directly causes buying behavior.

Our Weights & Odds Ratios

Positive Weight (OR > 1): Feature is associated with pushing probability and odds up.
Negative Weight (OR < 1): Feature is associated with pushing probability and odds down.
Near Zero Weight (OR ≈ 1): Feature has little to no association with predicted odds.

Stage 10

The Full Picture 🌟

You've walked through the entire logistic regression pipeline! Let's review the whole story in plain English:

The Story of Logistic Regression 📖

  1. We collect historical raw data: temperature, sunny weather, weekends, and whether someone bought ice cream.
  2. A straight linear regression line is not suitable because it predicts impossible values (below 0 and above 1) for probabilities.
  3. Instead, logistic regression builds an intermediate score called z by adding up weighted features (clues).
  4. The mathematical sigmoid function gracefully "squishes" this score z into a valid probability between 0% and 100%.
  5. A decision threshold translates probabilities into labels. Select it on validation data from error costs, prevalence and objectives; 0.50 is only a convention.
  6. During training, the model starts with baseline weights and iteratively adjusts them using gradient descent to minimize average log loss.
  7. A validation confusion matrix is used to compare threshold choices without touching the final test set.
  8. Performance is summarized using descriptive metrics: Accuracy (overall correctness), Precision (purity of Yes calls), Recall (capture rate of actual positives), and F1-score (their balanced harmony).
  9. The validation ROC curve and AUC summarize ranking trade-offs across thresholds during development.
  10. After the model and threshold are locked, the test set is revealed once for the final performance estimate.
  11. By analyzing coefficients and odds ratios, we can interpret how the model estimates each feature is associated with higher or lower odds of a purchase.
