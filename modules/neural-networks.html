Stage 01

The whole idea: learn patterns from examples

A neural network is a model made of small calculation units called neurons. Each neuron receives numbers, gives some of them more importance than others, combines them, and passes a new number forward.

Imagine teaching a child to recognize cats. You do not write every possible cat rule. You show many examples labeled cat or not cat. The child gradually notices patterns. A neural network does something similar with numbers.

→

Plain-English translation: examples go in, a prediction comes out, mistakes are measured, and the internal settings are adjusted so the next prediction is less wrong.

Normal programming versus machine learning

Normal programming: a human writes the rules, the computer applies them, and an answer comes out. Machine learning: a human supplies examples and correct outcomes, then the model learns useful rules from those examples. Neural networks are valuable when the rules are too numerous or complicated to write by hand.

Before you continue

You only need basic comfort with multiplication, averages, and percentages. Every specialist word is defined before it is used.

Stage 03

Clean, encode, scale, then split

Real data is rarely ready to train on. Missing values, duplicates, impossible values, inconsistent labels, and suspicious outliers must be investigated before the model sees them.

1. Clean

Fix or remove records that are missing, duplicated, impossible, or inconsistent.

2. Encode

Turn words and categories into numbers because the network performs mathematics.

3. Scale

Put numerical features on comparable ranges so a large unit does not look important merely because its number is bigger.

4. Split

Keep separate training, validation, and test sets so memorization cannot impersonate learning.

Training set ≈ 70% → teaches the model Validation set ≈ 15% → tunes choices during development Test set ≈ 15% → final, untouched exam

Keep the final exam separate: the test examples must not be used to teach or tune the model. Otherwise the final score no longer shows how well the model handles genuinely unseen data.

Academic precision

Why scaling is useful

What it prevents

A feature measured in thousands can dominate numerical updates even when it is not more meaningful.

What it does not mean

Scaling does not automatically decide which feature matters. The network still learns weights from the data.

Stage 04

A network is layers of tiny calculators

The input layer receives study, sleep, and attendance. Each hidden neuron receives its own weighted mixture of those inputs. Across training, different mixtures become sensitive to different combinations—perhaps high study with low sleep, or strong attendance with moderate study. These are emergent feature detectors: useful sensitivities discovered from data, not roles assigned to neurons by a person.

Stage 05

One feature has a different weight into every hidden neuron

There is not one universal “sleep weight.” Sleep connects to every neuron in the next layer, and each connection learns a separate value. One neuron may respond strongly to sleep, another weakly, and another negatively because it combines sleep with different evidence.

Stage 06

Non-linearity lets stacked layers learn bends

First ask why an activation is needed. If every layer performs only a linear weighted sum, stacking ten layers still collapses into one linear transformation. The network gains more arithmetic, but not a more flexible decision boundary.

inputs → weighted sum + bias → raw score → activation function → output signal
Boundary experiment

Use the buttons to focus either path; both remain visible for a direct comparison. Hidden layers use ReLU by default here. The output activation changes with the task:

↳

ReLU is a learned-pattern gate. A positive raw score passes as evidence that one learned pattern is present; zero means that neuron does not pass evidence for that pattern. It is misleading to say the network simply “throws away negative information”: other neurons—with different weights and biases—can represent opposing or complementary evidence.

Hidden layers: ReLU

ReLU(2.5) = 2.5 passes positive evidence; ReLU(-3) = 0 gates that detector off.

Binary output: sigmoid

One raw output becomes a score from 0 to 1, such as a pass score of 0.82.

Multiclass output: softmax

Several class scores are converted together into probabilities that total 100%.

Regression output: linear

The output remains a direct number because a probability constraint would be inappropriate.

Design decision: humans choose activations before training. Training learns the weights and biases that determine which patterns produce positive or non-positive raw scores.

Stage 07

Forward propagation makes one pass-score prediction

Forward propagation means information moves from the three inputs, through every hidden layer, to the single output neuron used by this binary task.

study + sleep + attendance → hidden-layer calculations and ReLU activations → one raw output score → sigmoid → pass score between 0 and 1

For one student, the output neuron might produce 0.82. We read that as an 82% model score for “pass.” The corresponding fail score is 1 − 0.82 = 0.18.

The output neuron does not yet make the final Pass/Fail decision. Stage 14 will apply a separate decision threshold, such as 0.50, to turn this continuous score into a class label.

Stage 08

Loss measures how wrong the prediction was

A loss function converts prediction error into a number. Smaller loss is better. Larger loss tells the training process that the current weights need more correction.

Regression

When predicting a number, mean squared error is common. It squares mistakes, so large errors receive extra punishment.

Classification

When predicting a class, cross-entropy loss is common. It strongly penalizes a model that is confidently wrong.

!

Loss is the teacher's marking pen. It does not merely say “wrong.” It gives the optimizer a numerical signal showing how much improvement is needed.

Do not confuse these

Loss versus metric

Loss

The quantity optimized during training. It guides weight updates.

Metric

A human-readable measure such as accuracy, precision, recall, MAE, or RMSE.

Stage 09

Backpropagation computes gradients—only gradients

A gradient is a collection of slopes: for each weight, it answers “if this weight increased a tiny amount, how would the loss change?” The sign gives a direction and the magnitude describes local sensitivity.

forward pass → prediction prediction + truth → loss backpropagation → gradient for every weight and bias weights are still unchanged

Backpropagation applies the chain rule from the loss backward through the network. It calculates how local changes connect to the final error. It does not choose a learning rate and it never updates a parameter.

Plain distinction: backprop computes gradients only. The optimizer later uses those gradients to update weights.

Stage 10

The optimizer takes iterative, local steps

Gradient descent applies the update. It combines the local gradient with a learning rate: next weight = current weight − learning rate × gradient. Because the gradient describes only the slope near the current point, optimization must repeat rather than jump directly to the answer.

Watch it walk downhill

Small steps need many updates. Medium steps descend efficiently. Large steps can overshoot and bounce away. Drag the current point on the curve to inspect a different local slope.

∇

What: a gradient is local slope. Why: it tells the optimizer which nearby direction lowers loss. How: multiply it by the learning rate and update. Why not one giant step? the landscape bends, and the local slope does not reveal the whole terrain.

Why local does not guarantee global

A low point reached from the current start may be a local minimum, while a lower global minimum exists elsewhere. Initialization, optimizer behavior, noise from batches, and the shape of the loss surface all affect the path.

Stage 12

Choose the model before validation gets worse

Training loss can keep falling while validation loss eventually rises. That is the causal signature of overfitting: the model is improving on examples it trains on while becoming less useful on unseen data. Keep the checkpoint near the lowest validation loss, not the final training step.

⌁

Local is not global: an optimizer follows nearby slopes and may settle in one valley even if a lower valley exists elsewhere. Validation asks a different question: whichever valley training reaches, does that model generalize?

!

Why can dependence be bad? A neuron might learn a brittle shortcut such as “attendance decides everything.” If later neurons rely heavily on that one pathway, the network may fail when the shortcut does not hold for new students.

Stage 13

Humans choose the architecture and hyperparameters

Parameters are learned by the model: every weight and bias. Hyperparameters are design decisions made before or around training.

Design decisions

Why each choice exists

Depth and width

Control representational capacity. Too little can underfit; too much can waste data and computation or overfit.

Activations

Add non-linearity and match output constraints. Hidden layers remain ReLU here.

Optimizer

Defines how gradients are converted into parameter updates.

Learning rate

Sets update scale: small is slow; large can overshoot.

Output-layer explorer

Binary classification

Hidden layers: ReLU. Output: one neuron with sigmoid.

Multi-class classification

Hidden layers: ReLU. Output: one score per class with softmax.

Regression

Hidden layers: ReLU. Output: usually one linear numerical value.

Feature engineering

Structured problems may improve when raw fields are turned into more useful clues, such as date of birth → age.

There is no universal “best” architecture. A design must match the task, data quantity, noise, complexity, and cost of mistakes.

Stage 14

The test set evaluates both scores and decisions

After training and tuning are finished, the model is evaluated once on the untouched test set. For our binary task, sigmoid first produces a pass score. A separate classification decision threshold then converts that score into Pass or Fail.

model pass score = 0.72 decision threshold = 0.50 0.72 ≥ 0.50 prediction = Pass

This threshold is not the school’s exam passing mark. It is the model’s cutoff for turning a score between 0 and 1 into a predicted class.

Decision control

Lowering the threshold predicts Pass more easily: recall usually rises, but false positives may increase. Raising it is stricter: false positives may fall, but more actual passes can be missed.

Stage 15

Error analysis starts with individual students

Overall scores hide which people are affected. Move the threshold, inspect the highlighted false positives and false negatives, and connect each case to the metric that represents its cost.

Case-level threshold explorer

Noor, score 0.68, actually failed: at the starting 0.50 threshold this is a false positive. If wrongly predicting success is costly, prioritize precision.

Sam, score 0.43, actually passed: at the starting 0.50 threshold this is a false negative. If missing a student who would pass is costly, prioritize recall.

Ana, score 0.57, actually passed: at the starting threshold this is a borderline true positive that flips when the threshold rises past 0.57. F1 is useful when both false positives and false negatives matter and one balanced summary is needed.

From case to action

Threshold changes only the decision rule; it does not repair weak features, biased labels, or poor calibration. Inspect concrete errors, diagnose the cause, change the appropriate part, then evaluate again by relevant groups.

Stage 16

Saving, deployment, and monitoring finish the lifecycle

Once performance is acceptable, the final model is saved. The saved package includes the architecture, learned weights and biases, and often the preprocessing rules needed to reproduce training-time inputs.

new user input → same preprocessing used during training → saved model → prediction → application response

Deployment puts the model into a website, mobile app, server API, edge device, or business system. A model sitting in a notebook is an experiment, not a working service.

After launch

Monitor accuracy, error types, input-data changes, speed, complaints, fairness, and security. When the world changes and performance falls, the model is experiencing drift.

Stage 17

Different network families organize information differently

Feedforward network

Information moves from input to hidden layers to output. This is the structure used throughout this lesson.

Convolutional network (CNN)

Common for images. Early layers notice edges; later layers combine them into shapes and object parts.

Recurrent network (RNN)

Designed for sequences and previous context, such as text, audio, and time series.

Transformer

Uses attention to connect relevant parts of data, allowing many relationships to be considered at once.

This layered transformation is called representation learning. Raw inputs become increasingly useful internal patterns: pixels → edges → shapes → objects, or word pieces → phrases → context.

Interpretability: weights are visible, but a representation is usually distributed across many parameters. Inspecting one large weight rarely yields a faithful human rule; use case-level explanations, sensitivity analyses, and validation evidence together.

Neural networks are powerful because they can learn complex representations. They are used for images, speech, text, translation, recommendations, medical scans, fraud detection, forecasting, game playing, and large language models. They are not magic: they still depend on good data, sensible design, testing, monitoring, and human judgment.

Final synthesis

One full training cycle

The causal chain
  • You choose the architecture, activations, optimizer, and learning rate.
  • Data enters and a forward pass produces predictions.
  • Loss converts prediction error into an objective.
  • Backpropagation computes gradients only.
  • The optimizer updates every weight and bias.
  • Updated parameters change the next forward pass.
  • Validation identifies the checkpoint that generalizes best.
  • Testing, deployment, monitoring, and error analysis keep the model accountable after training.
