Stage 01

The Raw Target

A regression tree is a model that helps us predict a number. Not a category like "cat or dog", but a continuous value like an exam score, temperature, or a house price.

Let's look at a small dataset of houses. We want to predict the Price (in thousands) based entirely on the Size of the house (in square meters).

Stage 03

The Clumsy Guess

At the very start, the tree puts all houses in one big group (the Root Node). Before asking any questions, it asks: "If I had to guess one price for all houses, what should I use?"

The standard answer is the average. If we take all 16 training house prices and average them, we get exactly $483.1k.

Root Prediction = Average(y) = 483.1

This is a clumsy guess. The red lines on the canvas show the Residuals—the mathematical distance (errors) between our flat guess and reality.

Stage 04

The First Split

Now the tree asks a question to divide the data: "Can I split the houses into 2 groups so the prices inside each group become more similar?"

It checks a "cut point". Based on the math, the best first rule is: Is Size ≤ 100?

If Yes, go Left. If No, go Right.

Now, instead of one average for everything, we have two averages. A lower average ($363.3k) for smaller houses, and a higher average ($637.1k) for bigger houses.

Stage 05

The Error Engine (RSS)

How did it know to split exactly at 100? The algorithm is "Greedy". It tests candidate split points between sorted training values and chooses the one that leaves the least amount of mess.

It measures "mess" using the Residual Sum of Squares (RSS). It squares all the red error lines and adds them up. Lower RSS is always better.

Stage 06

Real Trees Check Many Questions

In real machine learning, a regression tree is not limited to checking just one feature. It considers multiple input variables simultaneously, checking every possible partition point across size, age, rooms, and locations.

The tree runs a "Greedy Search": it picks the single feature and threshold that yields the largest drop in RSS.

Stage 07

Recursive Splitting

After finding the best first split, the tree does the exact same thing inside each new group. It splits, then splits inside the split. Like cutting a cake into pieces, then cutting those pieces again.

This is called Recursive Binary Splitting. With every split, the prediction line stops looking flat and starts looking like a set of stairs.

Watch the regions split and slide to form deeper nodes.

Stage 08

The Anatomy of a Tree

Even though we call it a tree, data scientists draw them upside down.

  • Root Node: The top, where all data starts.
  • Internal Node: A fork in the road where a decision is checked (e.g., Size ≤ 100).
  • Terminal Node (Leaf): The final box that gives the prediction number.
Interactive: Move your mouse over the canvas right now. The tree diagram will light up to trace the exact decision path for the region your cursor is in.
Stage 09

The Overfitting Trap

What happens if we never tell the tree to stop? It will keep splitting until every single data point is alone in its own leaf, creating a zero-error fit on training data.

This creates a massive risk of Overfitting—the model memorizes the random noise in our training set and fails to generalize to unseen houses.

Stage 10

Stopping Rules

To prevent overfitting, we enforce Stopping Rules (also known as pre-pruning). We restrict depth and control minimum partition requirements before splits can occur.

Validation Metric:
Metric Decoder
Error Actual price − predicted price.
RSS Σ(actual − predicted)²

Add up all squared errors. Excellent for comparing model error, though numbers become quite large due to squaring.

MAE average(|actual − predicted|)

Average absolute mistake. Easiest to explain because it matches the original unit ($k).

RMSE √average((actual − predicted)²)

Square root of average squared error. Expressed in original units ($k), but heavily punishes larger individual mistakes.

Example: If MAE = $30.0k, the model is off by about $30,000 on average. If RMSE = $33.0k, the typical error is about $33,000, with bigger mistakes punished more strongly.
Why compare Train vs Validation?
• Training Error tells us how well the tree fits the data it learned from.
• Validation Error tells us how well it performs on unseen, hidden houses.
• A deep tree can drive training error down to zero by memorizing noise, but will perform poorly on validation data.
• Rule of thumb: Always choose settings that minimize validation error. If two trees perform similarly, choose the simpler one!

How to Choose Stopping Rules
  • Do not choose the model based solely on the lowest training error.
  • Use validation error to estimate performance on unseen, real-world data.
  • Prefer lower validation error. Minimize this value to find the sweet spot.
  • If two settings perform similarly, always pick the simpler tree (Occam's razor).
  • Use both rules together: max_depth limits levels, while min_samples_leaf prevents tiny leaves that isolate individual outliers.

Notice that making the tree deeper eventually makes training error drop to 0, but the validation error starts increasing. That turning point is the sweet spot.

Stage 11

Pruning: Let It Grow, Then Cut It Back

Sometimes stopping early (pre-pruning) can be too short-sighted. It might stop before discovering splits that become useful in combination with other splits.

The alternative is Post-Pruning: We allow the tree to grow deep first, and then collapse weak, low-utility sub-branches back into parent leaf nodes using a complexity penalty called ccp_alpha.

Success: Complexity penalized. The weak bottom splits did not support generalization on validation data. Post-pruning successfully reduced validation error by 7.7% (from 7,100 down to 6,550)!

Look at the canvas to see the overgrown staircase collapse into a cleaner, stable staircase when pruned.

Stage 12

Trees vs. Lines

Linear regression fits a smooth, straight line. It assumes a constant rate of change. Regression trees carve the world into intervals and assign a flat average to each.

If the data has sudden thresholds or "if/then" behaviors, trees capture it naturally. If it's a smooth trend, lines win.

Stage 15

Reality Check: Limitations

While extremely powerful and explainable, single regression trees have key engineering limitations that you must look out for in practice.

Poor Extrapolation Trend Fail

Trees predict flat averages. If a house size is larger than any seen in training (e.g., 220 m²), the tree cannot continue a trend upward; it flatlines at the average of the largest leaf.

Jagged Step Predictions Staircase

Real-world factors often rise smoothly. Trees build staircases with sudden step jumps, struggling to cleanly represent smooth curves without huge depths.

High Instability (Variance) High Variance

A tiny shift in data (e.g., swapping one point's price) can completely re-arrange the root split boundary, producing a highly unstable prediction layout.

Axis-Aligned Splits Orthogonal

Basic trees split one feature at a time at right angles, making it difficult to capture diagonal correlations (like price dropping when size decreases and age increases simultaneously).

Easy to Overfit High Complexity

Without strict stopping rules or pruning, deep trees will easily grow until they isolate every single point, memorizing individual training points instead of discovering generalizable patterns.

Stage 16

Synthesis

Let's review the final sequence to build and use a regression tree:

1. Put all training data in the Root Node.
2. Test possible splits (greedy thresholds) across all available features.
3. Pick the feature/split that results in the lowest RSS.
4. Repeat the process recursively inside each new branch.
5. Use validation error to choose stopping rules or pruning, instead of trusting training error alone.
6. Each final leaf predicts the average target value inside that leaf.

While a single regression tree can be unstable on its own, this recursive logic is the fundamental building block for advanced modern algorithms like Random Forests and Gradient Boosting.

Ensemble Learning: Ensembles improve single trees by combining hundreds of them, smoothing out jagged steps and yielding highly stable predictions.
