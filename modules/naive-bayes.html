02Observe the case

Start with a pile of labeled emails.

Naive Bayes learns from examples where the answer is already known. In this miniature dataset, each row is an email, three clues are recorded, and the final column says whether the message was spam.

The model does not understand the sentence the way a person does. It sees a structured record: free? winner? meeting? and a class label.

AStart with the past. The model’s evidence comes from what happened in earlier examples.

03Frame the question

Separate the target from the clues.

The thing we want to predict is the target variable, Y. Everything else becomes a feature, X—a measurable clue the model can use.

For text, the original sentence is transformed into a vector of usable values. A word being present can become 1; absent can become 0.

X₁ = contains “free”→[1, 0, 1, 0]

04Protect the test

Keep the final exam hidden.

Before learning anything, divide the dataset. The training set teaches the model. The test set stays untouched until the end, so the final score tells us how the model handles examples it has not memorised.

A common starting point is around 80% training and 20% test. Peeking at the test set early gives an overly optimistic picture.

train = learntest = untouched

“Naive Bayes” is a family of models. The prediction logic stays recognisable, but the likelihood calculation changes with the kind of feature you have.

06Learn the starting belief

Count what each class tends to contain.

Training is mostly about learning probabilities from the training data. First comes the prior: how common is each class before we inspect the new email?

Then come the likelihoods: inside each class, how often did each clue appear? In a count-based model, this is a probability table made from the data.

P(Spam) = 40 / 100 = 0.40P(Free | Spam) = 30 / 40 = 0.75

07Make the naive move

Pretend the clues can speak separately.

Real words can be related. “Free” and “winner” may travel together. Naive Bayes deliberately ignores that relationship once the class is known.

This conditional-independence assumption is the shortcut: each feature contributes a separate piece of evidence, so the pieces can be multiplied together.

08Score a new observation

Prior × evidence = a class score.

Our new email contains “free” and “winner”. The model asks the same question twice: how well would this evidence fit Spam? How well would it fit Not Spam?

Use the switches to add or remove a clue. The bars and the normalised posterior update immediately.

09Change the kind of feature

Numbers need a different likelihood.

For a height, age, or temperature, counting exact matches is not useful. Nobody may be exactly 169 cm, but that height can still be typical of a class.

Gaussian Naive Bayes learns a mean and a spread for each class, then asks how normal the new number looks under each bell-shaped distribution.

Class A ≈ 168 cmClass B ≈ 181 cm

10Keep the arithmetic stable

Two small engineering fixes.

If a feature was never seen in a class, its count can produce a likelihood of zero. One zero would erase the whole product. Laplace smoothing adds a small artificial count so “unseen” does not mean “impossible”.

With hundreds of features, multiplying tiny numbers can underflow. Implementations use log probabilities: multiplication becomes addition, while the class ranking stays the same.

11Develop honestly

Use folds while you build.

Do not keep checking the final test set while tuning the model. Instead, rotate through the training set with 5-fold cross-validation: four folds train, one fold validates, then the validating fold moves.

After choosing the model, train once more on all training data. Only then do you test on the untouched 20%.

Round 1 · Fold 1 validates

12Read the result

A prediction is a decision with consequences.

Accuracy is not the only question. Precision asks whether predicted spam really was spam. Recall asks how much of the real spam the model caught. F1 balances the two.

In a spam filter, a false positive can bury an important email. The metric that matters most depends on the cost of being wrong.

Precision focus · keep false positives visible.

13Keep the mental model

Prior → likelihoods → posterior.

Naive Bayes is a detective with a disciplined shortcut: start with what was common, score how each clue fits each class, combine the evidence, then choose the most probable explanation.

Remember four words: prior, likelihood, naive assumption, and posterior.

What I believed before + what the evidence says = what I believe now.
