One-R

Start from raw rows, test every feature, keep the best one, and turn it into a tiny rulebook you can inspect without summoning a committee of neural networks.

Stage 01 · Observe

What problem is One-R solving?

Classification predicts a category, such as Yes or No. A feature is an input column. The target is the category we want to predict.

Our teaching sample records 14 days. Each row contains outlook, humidity, wind, temperature, and whether someone carried an umbrella.

The central question

“If I may inspect only one column, which column should I choose, and what should I predict for each of its values?”

Stage 02 · Baseline

First, make the lazy prediction.

Before building a model, count the target classes. There are 8 Yes rows and 6 No rows, so the majority classifier predicts Yes for every case.

majority accuracy = largest class count ÷ all rows
8 ÷ 14 = 57.1%

This baseline is intentionally dull. That is its job. A new classifier that cannot beat it has not earned its electricity.

Class imbalance warning. If 95% of rows are No, always predicting No scores 95% accuracy while learning nothing about Yes. Accuracy needs company.

If a dataset has 70 Yes rows and 30 No rows, what does the majority classifier predict?

Yes for every row, producing 70% training accuracy.

Stage 03 · Build

Make a rule from one categorical feature.

Choose a candidate feature, such as Outlook. Handle each distinct value separately and predict its local majority class.

1Collect all rows where Outlook is Sunny.
2Count Yes and No among those rows.
3Use the local majority as the prediction for Sunny.
4Repeat for Cloudy and Rainy.
Example rulebook
IF Outlook = Sunny THEN Umbrella = No
IF Outlook = Cloudy THEN Umbrella = Yes
IF Outlook = Rainy THEN Umbrella = Yes
error for a feature value = rows that disagree with that value’s majority class

Test every feature. Keep the lowest-error rule.

One-R repeats the same construction for every candidate feature. Each feature gets a rulebook and a total error count.

Stage 05 · Prepare

Turn numeric values into intervals.

A rule for every exact temperature would memorise the training sample and fail on a new value such as 23.6°C. One-R therefore discretises numeric values into intervals.

1Sort rows by the numeric feature.
2Group neighbouring values into sufficiently reliable buckets.
3Assign each bucket its majority class.
4Merge or adjust unstable neighbours according to the chosen implementation.
One possible training-only discretisation
Temperature ≤ 22.5 → Yes
22.5 < Temperature ≤ 27.5 → Yes
Temperature > 27.5 → No
Leakage alert. Fit cut-points using training data only. Choosing intervals after inspecting test labels is answer-shopping in a lab coat.
Stage 06 · Safeguard

Missing values and unseen categories are part of the model.

Real inputs are rarely as cooperative as textbook tables. Decide what happens when the selected feature is missing, a category never appeared during training, classes tie, or a number falls outside the observed range.

Stage 07 · Predict

Prediction is deliberately cheap.

Read the selected feature, find its stored value or interval, return the class, and use the fallback if nothing matches.

Prediction: Outlook = Cloudy → Umbrella = Yes. Humidity and wind are ignored because Outlook won training selection.

The model is saying Outlook is the strongest standalone predictor in this sample. It is not saying the other features have no relationship with umbrella use.

Stage 08 · Understand

One feature cannot express an interaction.

Suppose people carry umbrellas only when it is both cloudy and very humid. Neither feature alone may be strongly predictive, but their combination is.

useful pattern: Outlook = Cloudy AND Humidity = High

One-R sees

One column and one lookup table.

One-R misses

Interactions, gradual multi-feature effects, and alternative routes to the same class.

Interpretability is not innocence. A selected feature may be a proxy, unfair, operationally inappropriate, or merely associated rather than causal.
Stage 09 · Evaluate

Validate the whole learning process

Don’t judge the model only on the final prediction. Any choice the model makes—like selecting the best feature or building rules—must be done inside the training fold, then checked on data it has not seen.

1Split the data into folds
2Use the training fold to learn
Build buckets, test candidate rules, and choose the best option here.
3Freeze the rule
Stop changing it. No more label peeking.
4Test on the held-out fold
Predict unseen rows and record the error.
5Repeat and average
Run this across all folds, then average the results.
Grouped data: If several rows belong to the same person, device, or organisation, keep the whole group in one fold. Otherwise the model may recognise the group instead of learning a pattern that generalizes.
Stage 10 · Measure

Evaluate each fold. Decide what to do next.

Cross-validation gives multiple views of performance. Use the right metric for your goal, check stability across folds, and decide whether to proceed, tune, or collect more data.

1Choose the right metric

Pick the metric that matches the problem and the cost of mistakes.

Overall accuracy

Focus when classes are balanced and both types of errors matter similarly.

Best for: General performance check, balanced datasets.

Precision

Focus when false positives are costly (predicting Yes when it’s actually No).

Best for: Spam detection, fraud alerts, medical testing.

Recall

Focus when false negatives are costly (missing actual Yes cases).

Best for: Disease screening, churn prevention, safety monitoring.

2Measure stability across folds

Compute the chosen metric for each fold. Then summarize the stability.

CV stability % (coefficient of variation)

Measures how much the metric varies across folds relative to its average.

cv_stability_percent =
    scores.std()
    / scores.mean()
    * 100

Lower percentages mean more consistent performance from fold to fold.

Report all three (recommended)

Always look at these together for the full picture.

  • Mean (μ): average performance across folds
  • Standard deviation (σ): spread of performance
  • CV stability %: relative variation (lower is better)

Also check the min–max range across folds.

3Interpret stability (rule of thumb)

Use these as rough guides, not strict rules. Consider dataset size, domain, and the impact of errors.

CV stability %InterpretationWhat it means
<10%Very stableVery consistent across folds. Safe to proceed.
10–20%GoodGenerally consistent. Proceed with confidence.
20–30%AcceptableModerate variation. Still acceptable, but monitor.
30–40%InvestigateHigh variation. Investigate causes before proceeding.
>40%Potentially unstableUnstable across folds. Do not proceed yet.
Why this works: CV Stability % = (SD / Mean) × 100. Lower % means the metric changes little across folds relative to its average.

Key takeaways

One-R creates a majority-class rule for every value or interval of each candidate feature.

It selects the lowest training error, but performance belongs on held-out data.

Numeric buckets, fallbacks, ties, and missing values are fitted-model decisions.

Its value is transparent baseline reasoning, not pretending one feature explains the universe.

One rule. Surprisingly useful. Keep it beside stronger models as a readable benchmark and a fast warning system for suspiciously easy prediction.
