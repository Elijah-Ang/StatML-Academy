What does the model learn from?

Each email has measured clues and a known spam label. The training example has 40 spam and 60 ordinary messages. Those class frequencies give the model a starting probability before reading a new message's clues.

Try it

Count the 40 spam and 60 ordinary training emails. Divide by 100 to check the two starting probabilities.

Why this works · a little deeper

A prior is P(class), the chance assigned before observing this message's clues. Here P(spam)=40/100=.4. Training labels can contain errors and class frequencies may differ from deployment, especially if sampling was artificially balanced. A prior needs a justified source rather than being assumed true everywhere.

Quick check · If every clue is ignored, what is P(spam) in this example?

40 / 100 = 0.40. The absence of measured evidence leaves the prior unchanged.

02Separate features from the answer

What can the filter know at prediction time?

A word is an input clue. The spam label is the training answer, not an input available for a new email. For binary word features, 1 means present and 0 absent. Absent is different from ignored.

Message propertyRole
Contains “free”Input feature
Contains “winner”Input feature

Try it

Change “free” from present to absent, then to ignore. These are three different questions.

Why this works · a little deeper

Absent contributes the probability of not seeing the word within the class. Ignored means the clue is not observed for this calculation and contributes no factor. A full Bernoulli model normally includes both present and absent terms across its vocabulary. The lab allows partial evidence so you can build the calculation one clue at a time. Learn tokenization and vocabulary choices inside training too.

Quick check · Can “the user later marked this as spam” be a prediction-time feature?

Not if that action happens after prediction. It would leak the outcome into the inputs.

04Choose a likelihood for the feature

Why are there several kinds of Naive Bayes?

The Naive Bayes family shares a probability recipe. Different variants use different input types: word presence, word counts, categories or continuous measurements. Match the variant to what the numbers mean.

VariantFeature representation
BernoulliPresent / absent word
MultinomialWord occurrence counts
CategoricalOne of several named levels
GaussianA continuous measurement
↳
Try it

Choose a feature representation. Compare a present/absent bit with a word count or category, and explain what one displayed value means.

Why this works · a little deeper

Bernoulli models binary presence and absence. Multinomial uses feature counts, so three word occurrences differ from one. Categorical uses discrete feature levels. Gaussian fits a mean and variance for each continuous input within each class. The name alone does not turn a binary measurement into a continuous one. Check the representation and validation behavior.

Quick check · Is a word appearing three times identical to binary “present”?

Not as a representation. A count feature distinguishes one occurrence from three; binary presence does not.

Next: Count within each class ↓
05Count within each class

What does “given spam” mean?

Given spam means look only at the spam emails. Free appears in 30 of 40 spam messages and 6 of 60 ordinary ones. These fractions describe the word within each class, not the class among messages with that word.

ClueSpam: count / 40Not spam: count / 60
free30 / 406 / 60
winner24 / 403 / 60
meeting2 / 4030 / 60
P(free | spam) ≠ P(spam | free)
↳
Try it

Compare the free bars for spam and ordinary mail. Set smoothing to zero to see 30/40 and 6/60, then increase it and check what changes.

Why this works · a little deeper

P(free|spam) divides by all spam messages. P(spam|free) divides by messages with free. Bayes' rule links them using class priors and evidence. For binary smoothing α, likelihood=(count+α)/(class count+2α), because there are two outcomes. The printed counts are raw; the live receipt uses your selected smoothing value.

Quick check · Why is 30/40 not already P(spam | free)?

Its denominator includes all spam messages. We have conditioned on spam, not on the observed word.

Next: Name the naive assumption ↓
06Name the naive assumption

Why can we multiply the clues?

The model assumes clues act independently once the class is known. This lets us multiply their probabilities. Real words may still be related within a class, so repeated clues can make the result overconfident.

P(clues | class) ≈ ∏ P(clue | class)

“Free” copied into a second feature is the same evidence twice. Toggle the duplicate to see confidence change without receiving a new fact.

↳
Try it

Duplicate the free feature. Watch its factor appear twice and both class scores change. Did the message provide any new information?

Why this works · a little deeper

Conditional independence is an assumption inside each class, not a claim that words are unrelated across the whole inbox. Copying a feature repeats evidence rather than creating new information. Its changed posterior shows what happens when the model multiplies redundant clues as if separate. Validate rankings and probability calibration; neither check proves the assumption.

Quick check · Does a higher posterior after copying a feature mean we learned more?

No. We repeated information. The stronger posterior is an artifact of treating redundant features as independent.

Next: Turn scores into a posterior ↓
07Turn scores into a posterior

How does evidence become a probability?

For each class, multiply its starting probability by its clue likelihoods. These give class scores. Divide each score by the total of all class scores so the resulting probabilities add to one.

StepLive result
Spam score0.175737
Not-spam score0.004370
P(spam | selected clues)97.6%

Smoothing α = 1. Ignored features contribute no evidence.

↳
Try it

Add “meeting” as present. Follow its likelihood factor through both scores before looking at the posterior.

Why this works · a little deeper

Bayes' rule is P(c|x)=P(c)P(x|c)/Σ_k P(k)P(x|k). Σ means add over classes. The largest raw class score gives the same label as the largest normalized probability, but probability displays need normalization. If all scores are zero, the result is undefined. These are model probabilities, not guaranteed calibrated real-world risks.

Quick check · Do class scores have to add to one before normalization?

No. They become posterior probabilities only after division by their sum.

Why this works · a little deeper

Density is a curve height, not the probability of one exact continuous value. Probability comes from area over a range. Density units are inverse measurement units. Gaussian Naive Bayes combines class-specific densities and priors, all fitted from training. This separate height example uses equal class priors; it is not derived from email counts. Nearly constant features need a stated variance-stabilizing rule.

Quick check · Is the density at 170 cm the probability of a plant being exactly 170 cm tall?

No. Probability is area over an interval. Density is a height used to compare relative support at that measurement.

Next: Avoid zeros and tiny-number trouble ↓
09Avoid zeros and tiny-number trouble

Why add smoothing and use logarithms?

A zero likelihood wipes out a whole product. Smoothing gives unseen outcomes some probability. Logs turn products into sums, helping avoid numerical underflow. Smoothing changes the model; logs change the arithmetic used to calculate it.

log score = log prior + Σ log likelihood

“Unicorn” appeared 0 times in spam and once in ordinary mail. Try it with α = 0, then α = 1.

↳
Try it

Set unicorn to present and smoothing to zero. Increase α and inspect the repaired likelihood.

Why this works · a little deeper

For Bernoulli, adding α to both outcomes adds 2α to the denominator. For a multinomial vocabulary of V terms, the count denominator instead gains αV. Logs preserve order while avoiding a product becoming too tiny to represent. Stable normalization subtracts the largest log score before exponentiating. A zero likelihood has log −∞; all classes impossible remains undefined rather than invented.

Quick check · Does switching from products to log sums itself change the predicted class?

No, apart from numerical precision. Log is monotonic. Smoothing can change the model, while logs change how its arithmetic is computed.

What happens in one cross-validation round?

With five folds, train on four and validate on the fifth. Rotate that held-out group. Every scored row is predicted without training on it. Keep the final test outside this development loop.

Why this works · a little deeper

Cross-validation assesses a fitting procedure. Relearn vocabulary, feature selection and probability parameters in each training turn. Stratification can help class counts; groups or time address other structure. Searching many settings can overfit development scores, so a suitable outer evaluation or protected final test is still needed. Report the split design and uncertainty.

Quick check · May vocabulary selection run once on every fold before cross-validation?

No. If it learns from the data, fit it inside each training fold to keep validation independent.

11Choose a decision, not just a class

When should a message be flagged?

A probability becomes an action after we choose a cutoff. A lower cutoff catches more spam but can flag more ordinary messages. Choose the tradeoff using validation and the consequences of each mistake.

ErrorPractical cost

False negativeSpam reaches the inbox

Try it

Move the threshold past the current posterior. The evidence stays the same; the action changes.

Why this works · a little deeper

Precision asks how many flagged messages are actually spam; recall asks how many actual spam messages were caught. Those rates need many labelled predictions, not one posterior. A cutoff based on costs also needs credible cost and probability assumptions. Capacity, delayed labels and later class-frequency changes can matter. Changing the cutoff does not refit word likelihoods.

Quick check · Does changing the threshold retrain the word likelihoods?

No. It changes the action rule applied to the same estimated probabilities.

Next: Put the whole story together ↓
12Put the whole story together

What should you remember when using it?

Use available clues, protect evaluation data, choose the right likelihood type, fit counts and check the independence assumption. Then select and evaluate the decision rule. A confident probability is not the end of the evidence.

Use it when: a fast, interpretable probability baseline suits the feature representation.

Be careful when: evidence is strongly redundant, labels drift, rare categories dominate or probability calibration matters.

What to report: variant, feature construction, smoothing, split design, decision threshold, held-out metrics, calibration and limitations.
